### 🔴 #100 对齐跳字（最严重，已修 + 反向验证）

「起点越靠后 → 片段越短 → 待删 missing 越少 → distance 越小」→ 候选起点**不可比**，靠末尾的错误起点反而赢。

**修法**：`distance` **只累计认领区间**（`index < claimed_end`），与 `claimed_end` 语义统一；`extra` 仍全额计入。
**复现脚本**：`backend/scripts/_cn_trace.py`（真 provider + 真引擎，逐帧打印 partial 文本 / pos / matched）。

（原断言 distance==2，理由「含尾部未认领，否则不同起点不可比」—— 恰好写反），已改名并断言 distance==0。

### 🔴 #101 背诵页汉字下沿被裁（已修 + 反向验证）

且 `Clear-RecycleBin` 只清当前用户 —— C 盘回收站里有 5 个 SID 目录（SYSTEM / Administrator×2 / 用户×2），
**正解 = 逐个 `rm -rf C:\$Recycle.Bin\<SID>`**。

`safe-delete` 还有**批量守卫**：文件太多/太深/被占用 → `SAFE_DELETE_FAIL_CLOSED` 拒绝。
- `uv\cache` 2.1G 就是这么卡住的（分块也无效）→ 留给用户手动 `uv cache clean`
- `Windows.edb` 被 `WSearch` 服务占用 + 停服务需管理员 → 同上，给命令

**其他踩坑**：
- **PS 前台调用不回显输出** → 必须 `... | Set-Content 文件` 再 `Read` 那个文件
- **bash 的 `rm -rf` 好使**（被拦时触发 escalation 批准后真删）；`sc.exe`/`cmd.exe`/bash 调 powershell 全被安全策略拒
- 大目录删除单条命令 **5~15 分钟**，必须 `run_in_background`（本会话被 auto-background 打断多次）
- 判定删除是否生效：**`free` 没涨但 `recycle` 涨了 = 回收站问题**（用 PS 写文件交叉验证，别信 MSYS `du` 的延迟）
