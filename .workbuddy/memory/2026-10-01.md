## 语文背诵「卡住+按钮失效」排查（10:10-10:40，根因全链定位）
- 现场数据：recitation#13《背影》50 字，44.85s 音频仅 matched=16；09-29 几场 matched=0/5。后端日志 10:09:11「背诵 feed 失败：背诵已过期」→ error(abort) 下发后客户端零反应，82s 后二次 end 报「尚未 start 就 end」。
- **服务端链路本身是通的**：用 edge-tts 生成《背影》50 字音频（beiying_50_16k.pcm，ffmpeg 强制 -f s16le，第一次漏参数转成坏格式识别成'S W S'）跑 scripts/_cn_trace.py，50/50 全点亮，同音错（差事/差使、交谢/交卸、活/祸）全容忍。
- 根因（多因叠加）：
  ① 真实 partial 碎片化+学生卡壳念叨（transcript 全是「忘记/哎」碎片）→ engine 判噪声 → pos 不动 → 屏幕不亮 = 「卡住」体感；
  ② 客户端 feed 丢弃 is_noise，UI 零反馈；
  ③ 自动提示失效：partial 每 1-3s 来一次就 _resetSilence()，学生在念叨 → 8s 静音永不成 → 提示永不触发；miss_streak 只在非噪声对齐时涨 → 死锁：说话系统认为没静音、识别内容又对不上；
  ④ settle 竞态（硬 bug）：点结束 → settle HTTP 先 _drop_engine → WS final 慢一步 → _recite_feed 报「已过期」→ error(abort)；
  ⑤ recite_page._onWsMessage 只认 partial/final/result，**error 消息静默吞**（含①④的 abort）；
  ⑥ 按钮全废高危嫌疑：暂停/结束/重新开始都先 `await _recorder?.stop()`，record 插件录音流断后 stop() 挂起（安卓已知坑）→ 三按钮全无响应；录音流 onError: (_){} 静默、onDone 无处理 → 音频断了页面无感知。
- 复现工具沉淀：CN_PCM 环境变量 + scripts/_cn_trace.py 可完整复现语文流式链路（注册→建场次→建背诵→推 PCM→逐帧 pos/matched）。
- 待姚工拍板修复分层：服务端（settle 竞态降级、连续 noise 触发提示）/ 客户端（error 处理、录音流断感知、stop 超时保护、noise 轻反馈）。
