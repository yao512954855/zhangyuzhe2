## 今天修的四个坑（都值得记）
1. **glob 尾锚 bug**：`glob(f"*{suffix}")` 只匹配以 suffix 结尾的文件名，模型文件是 `encoder-epoch-99-avg-1.int8.onnx` → 改 `*{suffix}*.onnx`（local_provider + probe 两处）
2. **自写重采样混叠**：numpy 线性插值降采样（24k/44.1k→8k）无抗混叠滤波 → 声学特征全毁、识别全空。修法：按真实采样率喂 accept_waveform，让 sherpa 内部重采样器（带滤波）自己降
3. **data_dir 投毒**：tts_local._discover 因存在 lexicon.txt 就把 data_dir 指到模型目录，melo 没有 espeak-ng-data → sherpa 拿假 espeak 数据合成出近静音垃圾（云端判 ASR_RESPONSE_HAVE_NO_WORDS）。修法：data_dir 只认 espeak-ng-data 目录；melo 走 lexicon+dict_dir
4. **melo 短词韵律**：不带标点的短词合成极快极短（苹果 0.41s 被云端听成「那个」），带句号时长翻倍内容正确。ZH 自检短语须带句号

## 真机「拼读卡死」根因与修复（晚，契约修订 v1.0.3）

**需求澄清（姚工纠正我的理解）**：拼读是逐个单词来，念对自动跳下一个（不用手动）；「结束并结算」= 整轮背完才点。

**根因**（读后端日志实证）：App「看中文背英文」(spell_zh2en) 没有 end 入口（「我说完了」只在 en2zh），而 letter 判格只在 `_on_end` 触发 → 判格永不触发、字母格永远不亮、页面像卡死。日志佐证：8 分钟音频 partial 恒空、零 letter 零 final；且短词「APPLE」念完时 Vosk 直接进语句结束态，原实现把 `AcceptWaveform` 边界返回值丢了，确定结果只在 `Result()` 里，只有 close 才拿得到。

**修复（纯服务端，App 零改动、已装 APK 直接生效）**：
- `base.py` 新增 utterance 语句级回调（非幂等、不受 enable_intermediate 拦截、空文本/abort 不触发）
- `local_provider.py` Vosk 通道两条判格触发路径：① AcceptWaveform 边界 → Result()；② **服务端静音收口**：partial 停变化 ≥ SILENCE_FLUSH_MS(700) 主动取 Result()。（实测依据：22 条 qa spell 音频边界触发 0 次——整词一气念成尾静音不足；真人逐字母念靠路径②）
- `session_manager.py`：`_on_utterance` → spell_zh2en 有 target 即 `_spell_feed`；`_on_end` 的 spell 分支删重复判格（同文本重跑会对已推进游标错位重判）
- `mock_provider.py` close 时补发 utterance（模拟本地引擎语句级语义，保 WS 层用例覆盖）
- 关键设计：Result() 定版后内部清空，两条路径天然防重；`_spell_feed` 游标只前移，重复调用安全
- 契约 01 §1.3 记 v1.0.3；测试 +8（utterance 边界/静音收口/说话中不收口/非 spell 不产/session 级不等 end/守卫），全量 **331 passed**
- 验证脚本：`scripts/_verify_pause_spell.py`（拼接音频+静音，驱动真 LocalProvider：停顿 800ms → partial 稳定后 700ms 精确触发，字母独立成句 ✓）；`scripts/_verify_vosk_utterance.py`（22 条真实音频：close 残余通道 14/22，边界 0 次）
