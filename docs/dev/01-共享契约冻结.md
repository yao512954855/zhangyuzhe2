## 3. 统一响应的落地方式（后端）

`core/response.py` 提供两个函数，**所有接口必须使用**：

```python
def ok(data=None, message: str = "ok") -> dict: ...
def page(items: list, total: int, page: int, page_size: int) -> dict: ...
```

`core/errors.py` 定义：

```python
class BizError(Exception):
    def __init__(self, code: int, message: str, http_status: int = 200): ...

class ErrorCode:
    PARAM_INVALID        = 10001
    UNAUTHORIZED         = 10002
    FORBIDDEN            = 10003
    NOT_FOUND            = 10004
    TOO_MANY_REQUESTS    = 10005
    INTERNAL_ERROR       = 10006
    # 20000 段：账号与班级
    USERNAME_EXISTS      = 20001
    BAD_CREDENTIALS      = 20002
    ACCOUNT_DISABLED     = 20003
    CLASS_NOT_FOUND      = 20004
    # 30000 段：内容
    UNIT_NOT_FOUND       = 30001
    CONTENT_NOT_FOUND    = 30002
    CONTENT_HAS_RECORDS  = 30003   # 有记录不可删 —— 设计约束，非异常
    CONTENT_INACTIVE     = 30004
    # 40000 段：导入
    FILE_FORMAT_INVALID  = 40001
    TEMPLATE_COLUMN_MISSING = 40002
    IMPORT_VALIDATION_FAILED = 40003
    FILE_TOO_LARGE       = 40004
    # 50000 段：语音
    ASR_UNAVAILABLE      = 50001
    ASR_TIMEOUT          = 50002
    ASR_EMPTY            = 50003   # 不计错
    ASR_BAD_AUDIO        = 50004
    # 60000 段：服务发现
    DISCOVERY_FAILED     = 60001
```

**全局异常处理器**（BE-01 实现）必须兜住三类：`BizError`（按其 `code` 返回）、`RequestValidationError`（→ `10001`，附具体字段）、未捕获异常（→ `10006`，日志记完整堆栈，响应中只带 `trace_id`）。

**`trace_id` 规则**：每次请求生成 12 位十六进制字符串，写入日志上下文与响应体。**所有错误日志必须带 `trace_id`**，前端错误提示必须展示它。

### 4.2 写入方唯一性（并发安全的核心）

**一张表只有一个包拥有写权限**，其他包只能读。跨包写入一律通过服务层函数调用：

| 需要写 `word_mastery` 的场景 | 谁调用 | 实际执行者 |
|---|---|---|
| 英语答题后更新掌握度 | BE-04 自己 | BE-04 |
| 管理端查看「未掌握」筛选 | BE-03 **只读** | — |
| 统计聚合 | BE-07 **只读视图** | — |

> 违反这条（比如 BE-03 顺手 UPDATE 了 `word_mastery`）会造成并发写冲突与数据不一致，**明令禁止**。

### 4.3 连接与事务

每次建立连接必须执行（`core/db.py` 统一封装，业务代码不要自己写 PRAGMA）：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = NORMAL;
```

**写操作必须串行化**：SQLite 单写者模型，`core/db.py` 提供 `with write_tx() as conn:` 上下文，内部通过全局写锁保证同一时刻只有一个写事务。**所有写操作必须走这个上下文**，直接 `conn.execute("INSERT...")` 在并发下会抛 `database is locked`。

### 4.4 迁移规则

- `001_init.sql` **只写一次，之后永不修改**（包括"就补一个字段"也不行）。
- 新增结构变更 → 新建 `002_xxx.sql`、`003_xxx.sql`（编号递增，不得跳号复用）。
- 迁移文件必须**幂等可重入**：用 `CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`，`ALTER TABLE` 前先判断列是否存在。
- 启动时读 `schema_version` 最大版本号，依次执行未应用的脚本，成功后写入版本记录。
- **禁止手工改数据库结构**，禁止用 GUI 工具直接改表。

### 4.5 三条硬性数据约束（写入前必须校验）

| # | 约束 | 校验方 | 违反后果 |
|---|---|---|---|
| 1 | `texts.content_plain` 与 `texts.content_pinyin` **按空格切分后长度严格相等** | BE-03（导入时） | 语文对齐全盘错位 |
| 2 | `words.accepted` 必须是合法 JSON 数组字符串或 `NULL` | BE-03 | 判分时解析异常 |
| 3 | 有答题记录的内容（`answers`/`recitations` 存在引用）**只能停用不能删除** | BE-03 | 历史统计分子分母对不上 |

### 4.6 时间与布尔约定

- 时间统一 `TEXT` 存 ISO 8601 UTC：`2026-09-23T10:11:29Z`。**后端所有时间都要带 `Z`**，前端负责转本地时区展示。
- 布尔字段分两层处理：**数据库用 `INTEGER` 的 `0` / `1`**（SQLite 惯例）；**API 的 JSON 层统一用 `true` / `false`**，转换由 Pydantic 模型负责（`field_validator` 入口转 int，`field_serializer` 出口转 bool）。前端不接触 0/1。涉及字段：`require_spell`、`used_keyboard`、`appealed`、`is_correct`、`create_missing_units`、`history_affected`、`improved` 等。

## 5. HTTP 契约

### 5.1 基础

| 项 | 值 |
|---|---|
| Base URL | `http://{host}:{port}/api` |
| 认证头 | `Authorization: Bearer {jwt}` |
| 请求体 | `application/json`（上传用 `multipart/form-data`） |
| 分页参数 | `page`（1 起）、`page_size`（默认 20，上限 100） |
| 幂等 | 写操作支持 `Idempotency-Key` 头 |
| 业务失败 | **HTTP 200 + 非零 `code`**（前端统一在 `apiClient` 拦截） |
| HTTP 非 200 | 仅用于：400 格式错 / 401 未登录 / 403 无权限 / 404 路径不存在 / 413 文件过大 / 429 限流 / 500 服务异常 |

### 5.2 鉴权与角色

- 登录成功返回 `{access_token, token_type:"Bearer", expires_in, user:{...}}`。
- JWT payload 固定字段：`sub`（user_id）、`role`（`admin`|`student`）、`exp`、`iat`。
- 依赖注入（BE-01 提供，其他包直接用）：
  - `get_current_user` → `User`
  - `require_admin` → 非 admin 抛 `10003`
- Token 有效期默认 12 小时（学生端设备长期使用，可配置 `JWT_TTL_HOURS`）。

### 5.3 分页响应结构

```json
{
  "code": 0,
  "message": "ok",
  "data": { "items": [], "total": 128, "page": 1, "page_size": 20 },
  "trace_id": "8f3a2b1c9d0e"
}
```

### 5.4 限流（BE-01 实现中间件，按接口文档 §11）

| 维度 | 限制 |
|---|---|
| 单账号登录 | 5 次/分钟 |
| 单账号写接口 | 60 次/分钟 |
| 单账号 WebSocket | 1 路并发（新连接踢旧） |
| 全局 WebSocket | 60 路并发，队列 120，超出即拒 |
| 文件上传 | 10 MB |

## 6. WebSocket 契约 `/ws/asr`

### 6.1 连接

```
ws://{host}:{port}/ws/asr?token={jwt}
```

握手校验 JWT，失败关闭码 `4001`。**音频永远不直连云厂商**，一律经本机中转。

### 6.2 消息类型（冻结）

| 方向 | type | 载荷要点 |
|---|---|---|
| C→S | `start` | `session_id`、`task_type`、`lang_hint`、`hotwords[]`、`word_id`、`expected` |
| C→S | `audio` | **二进制帧**，PCM 分片（100–200ms/包） |
| C→S | `end` | 结束识别，触发最终判定 |
| C→S | `cancel` | 放弃本次（不计错） |
| C→S | `ping` | 心跳，每 30s |
| S→C | `started` | `provider`、`sample_rate`、`chunk_ms` |
| S→C | `partial` | `text`、`is_final`、`ts_ms` —— **语文逐字点亮依赖它** |
| S→C | `final` | `text`、`confidence`、`duration_ms` |
| S→C | `verdict` | `is_correct`、`match_type`、`expected`、`asr_text`、`normalized`、`answer_id`、`can_appeal`、`diff[]` |
| S→C | `error` | `code`、`message`、`ui_hint`、`action`(`retry`\|`keyboard`\|`abort`)、`fallback` |
| S→C | `pong` | 心跳回应 |

### 6.3 `task_type` 取值（冻结）

| 值 | 场景 | `lang_hint` | 判定方式 |
|---|---|---|---|
| `word` | 说单词 / 说短语 / 说句子 | `en` | `JudgeService.judge_text` |
| `spell` | 拼读字母 | **`zh`** ⚠️ | `JudgeService.judge_spell` |
| `zh_answer` | 英译中说中文 | `zh` | `JudgeService.judge_text` |
| `recite` | 语文背课文 | `zh` | `ReciteEngine.feed` |

> ⚠️ **`spell` 的语种是 `zh`，不是 `en`**（2026-09-23 预研修订）。这是**反直觉的**，实现时务必对照本表。
> `en` 会激活英语语言先验，**主动把字母串拼合成单词**（`C L A S S` → `Class`、`R E S T A U R A N T` → `Restaurante`），
> 使拼读判分下降约 10 个百分点。实测：`en` 85.0% → `zh` 95.0%。依据 `qa/ASR预研报告.md` §4.1。
>
> **语种由服务端按 `task_type` 决定，不信任客户端传入的 `lang_hint`**（映射表见 §9.2 `lang_map`）。

**安全红线**：`expected` 只用于**服务端判定**，绝不下发给云厂商；客户端在判定完成前**拿不到标准答案**。

### 6.4 `diff[]` 结构（冻结，驱动逐字母回显）

```json
{ "pos": 2, "expected": "a", "actual": "e", "state": "wrong" }
```

| `state` | 含义 | UI 表现 |
|---|---|---|
| `match` | 正确 | 正常显示 |
| `wrong` | 读错 | 高亮差异位，显示实际字母 |
| `missing` | 缺失 | 占位符 + 「这里没听到」 |
| `extra` | 多念 | 额外显示，标记多余 |

对齐算法在服务端执行，客户端只渲染。**客户端不得自行计算差异**。

### 6.5 断线与降级

> **语音优先原则（硬约束）**：语音是主交互，**键盘只是降级兜底**。降级必须由明确失败条件触发（**不得因单次失败就引导切键盘**），且必须留痕（`used_keyboard=1`）用于统计与优化。

- 断线自动重连 3 次，间隔 1s / 2s / 4s，携带 `last_answer_id`。
- 重连失败 → 当前题目切键盘输入，**不阻塞练习流程**。
- 云接口超时 >3s → `error.action = "keyboard"`。
- 连续失败 3 次 → 整个会话切键盘模式，录音本地暂存。
- 若 `asr.yaml` 的 `arbitrator.enabled = true`：在 `empty` / `fuzzy` / 申诉场景**先走多模态仲裁，仲裁仍失败才降级键盘**（需求 §9.7）。

## 7. 服务层接口契约（跨包调用的唯一方式）

> 这一节是**并发开发的解耦核心**。被依赖方必须先按此签名提供实现（可以是 Mock），调用方只认签名。

### 7.1 判分引擎（BE-04 实现）

```python
# app/services/judge/types.py
class DiffItem(BaseModel):
    pos: int
    expected: str | None
    actual: str | None
    state: Literal["match", "wrong", "missing", "extra"]

class Verdict(BaseModel):
    is_correct: bool
    match_type: Literal["exact", "loose", "fuzzy", "wrong", "timeout", "empty"]
    expected: str
    normalized: str | None = None      # 归一化后的学生答案
    asr_text: str | None = None
    can_appeal: bool = False
    asr_confidence: float | None = None
    diff: list[DiffItem] | None = None  # 仅 spell 返回

# app/services/judge/service.py
class JudgeService:
    def normalize_text(self, s: str) -> str: ...

    def judge_text(
        self, *, answer: str | None, expected: str,
        accepted: list[str] | None = None,
        asr_confidence: float | None = None,
    ) -> Verdict:
        """英语说词 / 英译中。规则见需求 §6.1。
        answer 为 None 或空 → match_type='empty'，is_correct=False（不计错）。
        """

    def judge_spell(
        self, *, asr_text: str | None, target: str,
        asr_confidence: float | None = None,
    ) -> Verdict:
        """拼读。谐音映射 → 去非字母 → 序列比对 + 编辑距离回溯出 diff。
        规则见需求 §6.2。目标长度 ≥6 且仅 1 处差异 → 'fuzzy' + can_appeal=True。
        """
```

**调用方**：BE-06（WebSocket 判定）、BE-04 自身（HTTP 答题接口）。
**Mock 约定**：在真实实现就绪前，Mock 只需返回一个 `Verdict` 对象即可，字段齐全、逻辑可简化。

### 7.2 掌握度服务（BE-04 实现）

```python
# app/services/mastery_service.py
# 唯一口径：not_started / practiced_with_error / practiced_ok / mastered
# 词条级与单元级共用同一枚举。判定必须按下列**优先级顺序**（先命中者胜），
# 否则「既 mastered 又有错」这类组合会产生实现分歧。
MasteryStatus = Literal["not_started", "practiced_with_error", "practiced_ok", "mastered"]

class MasterySnapshot(BaseModel):
    status: MasteryStatus
    streak: int
    mastered: bool

class MasteryService:
    def get_status(self, student_id: int, word_ids: list[int]) -> dict[int, MasteryStatus]:
        """批量查掌握状态，返回 word_id -> status。**O(1) 批量查询，禁止循环单查。**
        词条级派生（严格按序，命中即停）：
            1) total_count = 0            → not_started
            2) mastered_at 非空           → mastered
            3) wrong_count > 0            → practiced_with_error
            4) 其余（练过且无错）          → practiced_ok
        单元级派生（同枚举，接口 §8.3，严格按序）：
            1) 单元下无任何练习            → not_started
            2) 单元内全部词条 mastered     → mastered
            3) 有练习且有错                → practiced_with_error
            4) 有练习且无错                → practiced_ok
        """

    def update_after_answer(
        self, conn, *, student_id: int, word_id: int,
        is_correct: bool, match_type: str, duration_ms: int,
        hint_level: int, mastered_streak: int,
    ) -> MasterySnapshot:
        """在答题写入的同一事务内调用。conn 由调用方传入（已在 write_tx 中）。
        维护 streak / total_count / correct_count / wrong_count / hint_total /
        last_result / last_answer_at / mastered_at / avg_duration_ms。
        返回更新后的快照，供接口直接回传前端即时刷新（接口 §9.2 的 mastery 字段）。
        match_type='empty' 时**不得调用**本方法——识别为空不计入掌握度。
        """
```

**调用方**：BE-04（答题）、BE-03（学生端词条列表附掌握状态）。

### 7.3 背诵引擎（BE-05 实现）

```python
# app/services/recite/types.py
class FeedResult(BaseModel):
    pos: int                      # 推进后的指针位置
    newly_matched: list[int]      # 本次新点亮的字符索引
    is_noise: bool                # 判定为识别噪声，已忽略

class ReciteResult(BaseModel):
    total_chars: int
    matched_chars: int
    missed_chars: list[int]
    covered_ratio: float
    hint_count: dict[str, int]    # {"1":2,"2":1,"3":0}
    duration_ms: int
    first_voice_ms: int | None
    score: float
    grade: str                    # 优秀 / 良好 / 合格 / 待加强
    finish_reason: str

# app/services/recite/engine.py
class ReciteEngine:
    def __init__(self, *, content_plain: str, content_pinyin: str,
                 scope: list[int], window: int = 20, noise_threshold: float = 0.3): ...

    def feed(self, partial_text: str) -> FeedResult:
        """喂入 ASR 中间结果，增量对齐（拼音层），推进 pos。"""

    def check_auto_hint(self, silence_ms: int) -> int | None:
        """静音超阈值或连续漏字达阈值 → 返回应触发的提示档位（1..3），否则 None。

    def apply_hint(self, level: int, trigger_by: Literal["manual","auto"]) -> str:
        """降一档提示，返回该档应展示的内容（空框/首字/完整）。"""

    def finish(self, reason: Literal["completed","manual","timeout"]) -> ReciteResult:
        """结算，规则见需求 §6.4。"""
```

### 8.1 `match_type` 的语义（必须严格一致）

| 值 | 计对错 | 计入正确率 | 可否申诉 | 说明 |
|---|---|---|---|---|
| `exact` | 正确 | 是 | 否 | 完全一致或命中可接受答案 |
| `loose` | 正确 | 是 | 是 | 包含匹配（宽松命中） |
| `fuzzy` | 正确 | 是 | 是 | 相似度达标，机器有把握但存疑 |
| `wrong` | 错误 | 是 | 否 | 实打实答错 |
| `timeout` | 错误 | 是 | 否 | 限时到点（行为 A） |
| `empty` | **不计错** | **否** | 否 | 识别为空，单独统计，不进错题本 |

> 统计正确率时：分母 = 总数 − `empty` 数；分子 = `exact + loose + fuzzy`。**所有包必须用同一个公式**，写死在 `stats_service` 里，前端不重复计算。

## 12. 前端共享规范

### 12.1 管理端

- 统一走 `api/client.ts` 的 `request()`：自动带 Token、统一解包 `{code,message,data}`、`code != 0` 时抛 `BizException`（带 `code`、`message`、`trace_id`）。
- 401 → 跳登录；`10003` → 提示无权限；其他 → `ElMessage.error` 并附 `trace_id`。
- 全局错误提示**由 client 统一弹**，页面不重复弹。
- 表格分页统一用 `page/page_size`，不再各写各的。

### 12.2 学生端（护眼是硬需求）

- 主题 token 定义在 `core/theme/app_theme.dart`，三套主题：**日间暖白 `#F7F5F0`**、**纸质护眼 `#F5EEDF`**、**夜间深灰蓝 `#1B1F23`**。
- 对比度控制在 **8:1 ~ 12:1**，禁用纯白 `#FFFFFF` + 纯黑 `#000000` 组合。
- 字号分龄三档（正文/课文/触控目标）：1–3 年级 `18/36/64`；4–6 年级 `17/30/56`；7–9 年级 `16/26/48`。**下限 16sp / 48dp，不得突破。**
- **禁止 >3Hz 的闪烁动效**（光敏性癫痫风险）。
- 答错**不弹模态框**，只用内联反馈；答错音效不得用刺耳下行音。
- **语音优先**：麦克风是主交互入口；键盘入口视觉弱化、默认不引导，仅降级时启用（见 §6.5 与禁止清单 11）。
- 每 20 分钟弹护眼休息页（20 秒倒计时，可提前结束，不锁屏）。
- 所有页面必须适配「横竖屏」与安全区；练习页开启屏幕常亮。

> 完整规范见《背记系统UI设计规范》v1.0，**第 7 章页面清单是 APP 包的验收依据**。
