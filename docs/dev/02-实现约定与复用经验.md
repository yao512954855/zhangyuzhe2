## 一、全项目通用约定

- 接口一律用 `ok()` / `page()` 包装，**禁止直接 `return dict`**；业务失败 = **HTTP 200 + 非零 code**。
- **自动路由发现**：新增接口只放 `app/api/xxx.py` 并定义 `router`，**不许改 `main.py`**。
  - ⚠️ Starlette 路由**按注册顺序**匹配，同一路径重复注册会让其中一条**永久不可达**。
- **一张表只有一个写入方**（契约 §4.2）：
  | 表 | 唯一写入方 |
  |---|---|
  | `settings` | `SettingsService` |
  | `word_mastery` | `MasteryService`（BE-04） |
  | `users` | `UserService` |
  | `classes` | `ClassService` |
  | `units` / `words` / `texts` | `ContentService` |
- **正确率唯一口径**：`(exact + loose + fuzzy) / (总数 − empty)`，分母为 0 → 返回 `0.0`。
  **唯一实现 `UserService._accuracy()`**，其它地方不许再写一遍。
- **两步式导入**：`preview` 只解析校验（存 `core/preview_store`，TTL 30 分钟，**BE-02 / BE-03 共用同一份 store**）→ `commit` 凭**一次性 `preview_token`** 入库，靠 `preview_pop` 防重复提交。
- **`GET /api/import/report/{token}` 是一个 handler 服务三种导入**（学生名单 / 词条 / 课文），按 preview 写入 payload 的 `kind` 分派，表头由 `report_headers` 决定。
  ⚠️ 该 handler **归 `api/students.py` 持有**，其它包复用、**不要重复注册**。

## 二、账号域（BE-02）

- **登录防枚举**：账号不存在 / 密码错 / 角色不匹配 → **全部 `20002` 且文案一致**，且**三条路径都真跑一次 bcrypt**（用 `_timing_hash` 假哈希做时序对齐），否则响应时间会泄露账号是否存在。
- **登录锁定**：进程级内存计数，5 次失败锁 10 分钟（`LOGIN_FAIL_THRESHOLD` / `LOGIN_LOCK_SECONDS`），**不落库**。
- **重复导入 = 更新，且不重置密码**：只有该行 Excel **显式填了**「初始密码」才改 `password_hash`。防「手滑重导把全班密码刷回弱口令」。
- **`class_id` 三态**：字段**不出现**＝不修改 / `null`＝移出班级 / 有值＝归班。
  **必须用 `payload.model_fields_set` 判定** —— Pydantic 无法用默认值区分「不传」与「传 null」。

## 三、内容域（BE-03）

### 3.1 拼音与对齐（最易错）

- **`content_plain` 与 `content_pinyin` 严格等长**（契约 §4.5 硬约束）。
  - `content_plain` = **纯汉字序列**（去标点 / 空白 / 数字 / 字母，**不留空格**）
  - `content_pinyin` = **逐字无声调拼音、空格分隔**
- **拼音校验要严于「等长」**：`pypinyin` 对**不认识的汉字会原样返回该字符**（实测 `𠮷` → `'𠮷'`），长度仍 1:1 但**根本不是拼音**，对齐会**永久漏字且不报错**。
  → 规则：每个汉字必须产出 `^[a-z]+$` 的 token，否则 `pinyin_check='mismatch'` **并给出具体位置**，拒绝入库。
- **不要用 `heteronym=True`** —— 同字多音会让 token 数膨胀，破坏等长。
- 生僻字判定 `is_han()` **必须覆盖 CJK 扩展 B–F 区**，不能当标点丢掉。
- 中文标点是**不发音但占位**的：`split_paragraphs()` 按段落切，`build_scoped(paragraphs, scope)` 按背诵范围（**半开区间 `[start, end)`**）重算。

### 3.2 Excel 全角转半角（只对标识型字段）

`to_halfwidth` 覆盖**整个全角 ASCII 段（含中文标点）**，无差别使用会破坏展示数据：

| 字段类型 | 处理 | 例子 |
|---|---|---|
| **标识型**（英文、单元名、枚举、学号） | `to_halfwidth` + trim | `ＣＬＡＳＳ` → `CLASS` |
| **展示型**（中文释义、例句、课文正文） | **只 trim**（`clean_raw`） | `教室（改）` 保持全角、`，` 不被转成 `,` |

- Excel 侧：`read_xlsx(raw_columns=RAW_COLUMNS_WORDS/RAW_COLUMNS_TEXTS)` 声明哪些列走 `clean_raw`
- API 侧：`schemas/content.py` 的 `_clean_text()`（标识型）/ `_clean_show()`（展示型）
- 理由：数据库设计规定 `content_raw` **保留标点用于展示**，转半角会与之冲突。

### 3.3 内容增删改

- **停用内容不参与出题**：所有「给练习用」的查询**固定带 `status='active'`**；管理端列表**默认查全部**（含停用）。
- **词条 upsert 判重键 `(unit_id, en)`**：
  - `on_duplicate='overwrite'` → 更新内容字段，但**绝不覆盖 `status`**（防重导把精心停用的词条悄悄启用）；
  - `on_duplicate='skip'` → 全跳过，计入 `skipped`；
  - **绝不物理删除已有内容**。
- **改词条不回写历史**：`answers.expected` 是答题当时的**快照**。改完响应附 `history_affected: true`，由前端弹确认。
- **删除保护**（契约 §4.5 约束 3）：有答题记录的内容**只能停用不能删除**。
  - `answers.word_id` / `recitations.text_id` 是 `ON DELETE SET NULL`，**库不拦删除，必须服务层拦**。
  - 用 `EXISTS` 快速判「有没有」，**命中才** `COUNT(*)` 取 `record_count`（性能）。

### 3.4 双角色同路径（契约 §14 裁决 3）

`GET /api/units/{id}/words`、`GET /api/units/{id}/texts` 按角色裁剪：

| | admin | student |
|---|---|---|
| 字段 | 全字段 | 隐藏 `accepted` / `status`，按 `mode` 藏 `en` 或 `cn`，附 `mastery` |
| 分页 | `page()` 分页 | **不分页**（§8.5 要求一次给全，供 App 本地缓存离线练习） |

> ⚠️ **`accepted` 绝不下发学生端**（等于泄题）。

### 3.5 掌握度（只读）

`word_mastery` 唯一写入方是 **BE-04**。BE-03 只读，且 `MasteryService` 未就绪时**降级到本地 `_derive_status()`**（规则与契约 §7.2 一致）。批量取用 `mastery_map()`（O(1) 查表，避免 N+1）。

## 四、练习与判分域（BE-04）

### 4.1 判分（需求 §6.1 / §6.2）

两套规则**刻意不对称**，不要"统一"它们：

| | 文本判定（说词 / 英译中） | 拼读判定 |
|---|---|---|
| 流程 | 五级顺序，命中即停 | 三级顺序，命中即停 |
| 模糊门槛 | 相似度 ≥ **0.85** 且目标长度 ≥ **5** | 编辑距离 ≤ **1** 且目标长度 ≥ **6** |
| 相似度算法 | `difflib.SequenceMatcher.ratio()` | 不适用（用编辑距离） |
| diff | **无** | **必有**（非 empty 时） |

- **拼读门槛比文本严（6 > 5）**：拼读串更短、字母更易混，短串上「差 1 位」不足以说明真会拼。
- **同音词不自动等同**（需求 §6.1 明文）：`there` / `their` 判 `wrong`，只有显式配了
  `accepted` 才算对。同音词正是英语学习的重点。
- **`empty` 一律不计错**，且**不写 `word_mastery`**（契约 §7.2 明文）。

### 4.2 归一化（两套，不可混用）

| 函数 | 用途 | 保留什么 |
|---|---|---|
| `normalize_text` | 说词 / 英译中 | **词间空格**（`a classroom` 要能和 `classroom` 做包含匹配） |
| `normalize_letters` | 拼读 | **只有 a–z** |

- 转小写、全角转半角、标点→空格（**撇号按语境保留**：左右紧邻都是 ASCII 字母才算撇号，
  这样 `don’t` 的弯引号能留住、`‘你好’` 的中文引号会被剥掉）。
- **中文数字 → 阿拉伯数字**，但**只转整段可解析的**：`十一`→`11`、`一百零五`→`105`；
  `两三` / `二零二六` 这类歧义写法**原样保留**。宁可漏转，不可猜 —— 与
  「判分模型必须忠实」是同一条原则。
- 汉字**之间**的空格要去掉（中文不按空格分词），但中文与英文之间的空格保留。

### 4.3 谐音映射表（`app/data/homophone_map.yaml`）

三层匹配，**优先级从高到低**：

| 层 | 用途 | 例子 |
|---|---|---|
| `words` | **整串**精确匹配 | `克拉斯` → `class` |
| `tokens` | 多词组合（贪心最长） | `double u` → `w` |
| `letters` | 单 token / 逐字符 | `see ell aye ess ess` → `class` |

- **`words` 层必须存在**：`克拉斯` 是三音节音译、对应 `class` 五个字母，
  逐字符规则**永远得不到**正确结果，只能整串登记。
- **不做模糊猜测**：查不到就读作原字符，由「去非字母」自然丢弃。宁可漏，不可把错读判对。
- ⚠️ **`_scan` 的逐字符最长匹配 + 读音歧义会凭空造字母**：R 的读音登记了 `ar`，
  则 ASR 返回的 `are` 会被拆成 `ar`+`e` → `re`，`classroom` 变成 `classreoom`。
  **修法是往表里补整词读音（`are`）**，不是改算法。
  - 同理，同一读音映射到多个字母时**保留先出现的**（字母按 A→Z 书写，行序即优先级），
    并在加载时打 warning。已刻意把 `丝` 从 C 移走（与 S 的 `斯` 同音）。

### 4.4 逐位对齐（`diff[]`）

`diff` 是**硬需求**（需求 §5.4），不论对错都要产出。两个关键决策：

1. **长度相等时直接逐位比**。走 DP 的话，`class` vs `cless` 也会被解释成
   「少 a 多 e」，产出 `missing` + `extra` 两条；而学生要的是
   「第 3 位听成 e，应为 a」这一条 `wrong`。
2. **长度不等时回溯偏好 `extra` > `missing` > 对角**。`classs` vs `class` 两种路径
   编辑距离都是 1，但「末位多念了 s」才是学生能理解的说法。

`extra` 位 `expected=None`、`missing` 位 `actual=None`，`pos` 连续从 0 起。

### 4.5 练习流程口径

- **组卷一次性生成完整题序**，`items` 里**只有题目侧字段**（`prompt` / `target_len` /
  `example_cn`），`expected` 判定后才下发（禁止清单 4 / 7）。
  - `cn2en`：`prompt = cn`，`require_spell` 取词条配置；`en2cn`：`prompt = en`，
    **`require_spell` 强制 false**（需求 §5.5 该模式不要求拼读），且不给 `example_cn`。
- **一个词条 = 一项**（F14）；`cn2en` 且要求拼读时**两步都对**才算该项正确。
  「只提交第一步」也算错 —— 否则可以用少提交来刷分。
- **`accuracy` 分母 = 组卷项数 − 全 `empty` 的项数**（U25）。
  某项名下**所有**记录都是 `empty` 才算 `empty` 项。
- **`answers` 表没有 `score` 列**（DDL 冻结，不可改）。单题分数只在答题响应里给；
  结算时按同一规则（`score_answer()`）**重算**，绝不另写一份公式。
- **`wrong_items[].match_type` 取「判错的那条」记录**，不取最后一条：
  学生可能先说错、再用宽松命中补答对，取最后一条会让前端看到
  「判错清单里躺着 `loose`」自相矛盾。
- **限时到点（F15）**：行为 A 判 `timeout` 计错；行为 B **不写答题记录**（才真的"不计对错"），
  响应 `skipped=true`；行为 C 正常判定 + 响应 `timed_out=true`。
  客户端会传 `timed_out`，但服务端**同时**按 `duration_ms >= time_limit_ms` 兜底 ——
  判定相关输入一律服务端可复核。
- **幂等（F20）零代码**：BE-01 的 `IdempotencyMiddleware` 已覆盖，本包只补测试。

### 4.6 掌握度（`word_mastery`，BE-04 唯一写入方）

- **词条级派生**（严格按序，命中即停）：`total_count==0` → `mastered_at` 非空 →
  `wrong_count>0` → 其余。
- **单元级派生**（同枚举，严格按序）：单元无练习 → 全部词条 mastered → 有错 → 无错。
  ⚠️ 「无练习」必须在「全部 mastered」**之前**：空单元的「全员掌握」在集合论上为真，
  但语义上应是「未练」。
- **答错立即清零**：`streak=0`、`mastered_at=NULL`（需求 §6.5）。
- `avg_duration_ms` 用**增量平均**（`(avg*n + d) / (n+1)`），不为一个均值去读全部历史。
- 连对门槛 `mastery_streak` 走 settings（默认 3）。
- ⚠️ **契约 §7.2 写的是实例方法（`self`），但 BE-03 已按类方式调用**
  （`content_service.py::_statuses_from_mastery_service`）。本包实现为 **`classmethod`**，
  使 `MasteryService.get_status(...)` 与 `MasteryService().get_status(...)` **都成立** ——
  若照抄 `self` 会静默走进 BE-03 的 `except` 分支，退化成降级派生，且**不报错**。

### 4.7 错题本与申诉

- **错题本取 `word_mastery` 物化表**（§8.8 明文），不去聚合 `answers`。
- **申诉只置 `appealed=1`，绝不改 `is_correct` / `match_type`**（§8.9）；
  仅 `loose` / `fuzzy` 可申诉；**必须校验归属**（不属于当前学生 → `10004`，
  且不区分「不存在」与「不属于你」，避免探测他人记录）；重复调用幂等且**不重复写审计**。

## 五、语文背诵域（BE-05）

### 5.1 拼音层对齐（需求 §6.3 硬要求）

汉字识别必然带同音字错误（的/地/得、在/再、他/她/它），**必须在拼音层比对**，同音字自然通过。
与 `judge/spell_judge` 的**字符级**编辑距离不同：拼音是**多字符 token**（`zhong` / `guo`），
必须按 **token 序列**做 DP，回溯偏好 `extra > missing > 对角`。

- **多音字必须宽松匹配**：`pypinyin.lazy_pinyin("地")` 默认给 `di`，课文里读 `de`。
  用 `pinyin(heteronym=True)` 取**全部读音集合**做比对（`readings()` 带 `@lru_cache`），
  **不动 `content_pinyin` 的生成方式**（已入库冻结）。
- **只取汉字**：标点 / 数字 / 英文不进拼音序列，与 `content_plain` 口径一致。

### 5.2 认领边界 `claimed_end`（本轮最关键的概念）

对齐片段**故意比识别文本长一截**（`allowance = window`），为的是识别「**跳字继续背**」：
学生漏两个字接着往下背、后面全对，不能因为窗口太短就整段判错。

代价是：**片段尾部未被认领的 missing 是「还没背到」而不是「漏了」**。
故推进指针用 `pos = max(pos, alignment.claimed_end)`，
**漏字只统计 `claimed_end` 区间内的**（`trailing_miss`）。
→ 这条不做，U1 立刻回归（尾部未认领的字被算成漏字、指针直冲末尾）。

### 5.3 评分（规格自相矛盾，按需求 §6.4 + U15 执行）

`score = 60×cover + 25×accuracy + max(0, 15 − 5×hints)`；
`cover = 已认领字数 / 总字数`，`accuracy = 1 − 漏字数 / 总字数`。
评级：≥90 优秀 / 75–89 良好 / 60–74 合格 / <60 待加强。

⚠️ 10b 正文写的 `15×max(0, 1 − hints×0.05)` 与 U15 预期（85 分）**算不出来**，见待裁决清单。
**空课文（`total_chars ≤ 0`）直接返回 0**，否则白送 15 分提示分。

### 5.4 提示档位

`level = min(3, max(silence_ms // silence_hint_ms, miss_streak // miss_streak_hint))`。

- **同一位置不重复触发**（U8/U9）：档位只升不降，`_hint_ceiling` 记已下发过的最高档。
- **`/feed` 返回的「建议档位」必须无副作用** —— `peek_hint_level()` 只算不记。
  忘记这点，客户端随后真调 `/hint` 会拿不到档位（已被 feed 消耗）。
- 档 3 = 给出**下一个字 + 后续 4 字**。

### 5.5 结算与防刷分（F5 硬要求）

- **settle 忽略客户端的 `matched_chars` / `missed_chars` / `hint_count`**，
  用 `transcript` 在服务端**重跑对齐**（烟测专门验证「谎报无效」）。
- **实时引擎是进程内存**（`ReciteService._engines` 按 `recitation_id` 缓存），
  进程重启丢状态 → settle 时按 `scope_snapshot` + `transcript` **重建引擎**再算，
  因此「无实时状态也能结算」成立。
- **幂等**：`recitations` 已有结果则直接返回，不重复写 `recitation_events`。

### 5.6 语文场次（契约 §9.1 只定义英语，BE-05 补齐）

`POST /api/sessions` 按 `content_type` 分派：英语走原逻辑，语文走 `_create_chinese_session`
（`items` = 课文清单，带 `recite_scope`）。

- **段落偏移只累计 `recite_scope` 内的段落** —— `texts.content_plain` 是导入期 `build_scoped`
  生成的、**只含背诵范围内的字**；按全段累加偏移会让「范围不含首段」的课文整体错位（本轮已修为真实缺陷）。
- **settle 不关场次**：背完一篇就把 `sessions.status` 置 `finished`，第二篇就开不出来了。
  需要收口时调 `POST /api/sessions/{id}/finish`（`_finish_chinese_session` 按篇汇总，**字为口径**）。

### 5.7 接口与文件

`app/api/recite.py` → `POST /api/recitations`、`/feed`、`/hint`、`/restart`、`/events`、`/settle`。
`feed` 的 `partial_text` 是**累计全文**（`_consumed_len` 只消费增量），**不是本段增量**。

## 六、语音网关域（BE-06）

### 6.1 契约没写的三处语义（本包补齐并上报）

契约 §7.4 的 `ASRProvider` 只有五个方法，**没有 `end` / `cancel`**，但 WS 协议必须有这两个动作：

| 语义 | 本包约定 |
|---|---|
| 结束识别并产出 `final` | **`close()`** —— 若尚未产出 `final` 就先 flush 再回调 `on_final`，然后释放云端连接；**幂等** |
| 放弃本次（WS `cancel`，不计错） | **`abort()`** —— 基类具体方法（非契约方法），置 `_aborted` 后调 `close()`，**不触发 `on_final`** |
| Provider 回调是**同步**签名 | 回调只往 `session.outbox` **append**；由 pump 任务顺序发出（**回调里不能 await**） |

### 6.2 MockProvider 不是「可选项」，是并行开发的地基

F4 明文要求，但它真正的价值是：**没有云账号也能把 APP-02/03/04 全部联调完**。
因此必须**行为可脚本化**：`behavior ∈ normal/empty/timeout/error/connect_fail`、
`fail_times`（前 N 次建连失败 → 测主备切换）、`partial_every`、`by_task`（按题型覆盖脚本）。

⚠️ **`asr.yaml` 里各 Provider 读的是自己的段**（`config["aliyun"]` / `config["mock"]`），
但单测常常直接传扁平 dict —— **两种写法都必须支持**。
早期 `MockProvider` 只认扁平写法，于是 `asr.yaml` 的 `mock.final_text` 读不到，
**Mock 永远返回空串且不报错**（表现为「判定永远 empty」，极难定位）。

### 6.3 配置读取的两个静默失效坑

- **pydantic 会丢掉 extra 字段** —— `ASRConfig`（BE-01）里没有 `mock` / `limits`，
  用 `get_asr_config()` 拿**运行时编排参数**会静默变成默认值。正确做法：另走
  `load_asr_raw()` 读**原始 yaml dict**，并支持 `ASR_CONFIG_PATH` 环境变量覆盖
  （否则测试与烟测只能去改真配置）。
- **`_write_asr_yaml(arbitrator=...)` 写错层级** —— 把 `arbitrator` 塞进 `mock:` 段，
  仲裁「看着已启用」实际没生效。**临时配置的构造要区分「顶层」与「子段」两套参数。**

### 6.4 WebSocket 的两条硬规矩

1. **要用自定义关闭码，必须先 `accept()` 再 `close(code)`** ——
   不 accept 直接 close，Starlette 只能回 HTTP 403，客户端**永远拿不到 4001**。
   对应地，测试里的断言点必须在 `receive()` 上：`websocket_connect` 的 `__enter__` 只做握手。
2. **收帧不要 `asyncio.wait_for(ws.receive(), timeout)` 轮询** ——
   超时那一刻会**丢掉刚好到达的帧**。改用「后台 reader 任务 + `asyncio.Queue`」，
   主循环对队列做 1s 超时取，既能判心跳又不丢帧。

### 6.5 音频「不落盘」与仲裁「要用音频」的折中

F18 要求音频不落盘；F19 仲裁又要拿音频做第二判据。折中：**只在内存里保留最近
`arbitrator.buffer_ms`（默认 15s ≈ 480KB）**，任务结束立即释放。
60 路并发约 28MB —— 可接受，且仍然一个字节都没落盘（U15 有断言）。

### 6.6 `asr_logs` 的外键会吃掉整条日志

`asr_logs.session_id` / `student_id` 都有外键。客户端传了**过期场次 id** 时，
`INSERT` 因外键失败 → **整条日志丢失**，用量统计凭空少一截。
做法：**降级重试（把两个外键置空）**，保住 `provider`/`model`/`status`/`latency_ms`
这些统计字段；同时**写日志的任何异常都吞掉**（日志不能拖垮语音链路）。

### 6.7 归档位置

- 服务层：`app/services/asr/{base,mock_provider,aliyun_provider,volcengine_provider,factory,hotwords,arbitrator,session_manager}.py`
- 日志：`app/services/asr_log_service.py`
- 端点：`app/api/asr_ws.py`（**只搬帧，状态机全在 service 层**，这样 U2~U16 能用假 send 跑）
- 配置：`backend/asr.yaml`（密钥，已 gitignore）+ `asr.yaml.example`（模板，可入库）

## 九、复用经验（跨项目）

> 已固化为 skill 的（**动手前先看有没有现成的**）：
> `vue-admin-shell-bootstrap`（Vue 管理端骨架 + 无头浏览器验收）、
> `flutter-android-env-setup`（Windows Flutter 安卓环境）、
> `asr-pilot-evaluation`（语音应用 ASR 选型预研工作流）、
> `contract-first-workpackages`（契约冻结式工作包拆分）、
> `spec-compliance-audit`（规格合规审计 + 反向验证）、
> `md-to-word-zh-report`、`mermaid-diagram-check`。

### 序列对齐（拼音 / 文本 diff 通用）

- **「窗口故意开大」和「统计口径」必须拆开** —— 对齐时给窗口留 allowance（为了认出跳字继续背），
  但统计漏字时要把**尾部未认领**的部分排除（那是"还没背到"）。
  混在一起就是「对齐对了、统计全错」，且只在**结尾有跳字**的用例上暴露。
  写法：先定 `claimed_end`，再在 `[start, claimed_end)` 区间里数 matched/missed。
- **多音字是真实缺陷，不是噪声** —— 课文里 `快乐地跑` 读 `de`，词典默认给 `di`。
  判定层要接受**读音集合**（`heteronym=True`），而不是单读音。同类：`着`/`了`/`不` 的变调。
- **回调/查询类方法默认要无副作用** —— `peek_hint_level()`（只算）与 `check_auto_hint()`（记档位）
  必须拆成两个函数。客户端先问建议、再决定要不要真的要提示，是很自然的交互，
  一旦"问"就把档位消耗掉，后续真调就静默失效。
- **进程内缓存 + 进程重启 = 状态丢失**：引擎状态放内存（快），但 settle 必须能从
  **落库的快照 + 原始输入**重建。别把"能重建"当成可选项 —— 后端重启是常态。

### Python / FastAPI

- **模块级 `settings = get_settings()` 是快照，运行期逻辑一律现取 `get_settings()`。**
  症状：测试换库不生效 → admin 建在新库上却用旧库的密码 → 登录报 `20002`，**只在多模块混跑时暴露**。
  （已修 `main.py::_ensure_admin_account` / `bootstrap`，模块级 `settings` 仅保留给 import 期初始化。）
- **`os.environ` 是进程级的，`SettingsService._cache` 是类变量** —— pytest 混跑多个测试模块时，每个 fixture 必须**自给自足地重设环境变量 + 清类变量缓存**，并断言 `get_settings().db_file` 确实指向自己的临时库。
- **`Exception` 全局处理器运行在最外层 `ServerErrorMiddleware`**，位于所有用户中间件之外 —— 中间件用 contextvars 传的值在异常穿出时**已被 reset**。
  解法：**额外把值写进 ASGI `scope`**，处理器里再恢复。中间件一律**写纯 ASGI**（`BaseHTTPMiddleware` 会另起 task，contextvars 同样不可靠）。
- **HTTP 响应头取出后别转 `dict`** —— ASGI 出口的头是小写，转字典丢掉大小写不敏感特性，`.get("X-Trace-Id")` 会静默返回 `None`。这通常是**验证脚本自身的 bug**，易误判成产品 bug。
- **拼 SQL 时，`LEFT JOIN` 是可选的，`SELECT` 里的 `m.xxx` 不是** —— 条件拼接 join 时极易漏改 `SELECT` 列表，症状是 `sqlite3.OperationalError: no such column: m.wrong_count`，且**只在没触发 join 的分支上暴露**（本次是 `scope='unit'` 这一条最常用的路径挂了）。
  写法：`wrong_count_sql = "COALESCE(m.wrong_count,0) AS wrong_count" if join_mastery else "0 AS wrong_count"`。
- **DDL 是冻结的，动手前先 `PRAGMA table_info` 核一遍要写的列。** 本次栽在 `answers` **没有 `score` 列** —— 契约禁止改 `001_init.sql`，所以"单题分数"只能算出来就返回、结算时再按同一函数重算，**绝不能自己加列**。同类风险项：`sessions` 没有 `accuracy`/`ended_reason` 列。

### 长连接 / 流式网关

- **状态机放 service 层，端点只搬帧** —— 出站消息走**注入的 `send` 协程**而非直接持有
  WebSocket 对象。收益：绝大多数验收用例能用「假 send + 假 Provider」在纯单测里跑完，
  真机烟测只补「真网络」那几件事（真握手、真关闭码、真并发）。这个分层一次做对，
  后面每个用例都省一轮起服务。
- **自定义关闭码必须先 accept**：不 accept 直接 close，ASGI 只能回 HTTP 403（见 §6.4）。
- **不要用 `wait_for(receive())` 轮询长连接**：超时会丢帧，用「reader 任务 + 队列」。
- **对外部依赖（云厂商 / 数据库）的「旁路能力」必须能关闭**，且关闭后行为与不存在时**完全一致**；
  触发条件要**写死在代码里**（如仲裁只允许 empty/fuzzy/申诉），不能靠配置自觉 ——
  一次配错就变成主链路秒级延迟 + 按 token 计费。
- **日志/审计类写入降级**：FK 或约束失败时，宁可丢归因字段也不要丢整行；
  且**任何日志异常都吞掉** —— 主链路不能被日志拖死。

### 工具链 / 环境

- **同一文件在同一消息里发多个 Edit 会互相覆盖**（都报成功，只有最后一个写盘生效）—— **必须串行**。
- **独立脚本 import 后端模块前先 `sys.path.insert(0, str(BACKEND))`**。烟测脚本通常放在 `backend/scripts/`，`sys.path[0]` 是 `scripts/`，`import app.xxx` 会报 `ModuleNotFoundError`。放进函数里（而不是模块顶部）会让它在调用点才炸，报错位置离根因很远。
  - **子进程版要另加一条**：把「造数脚本」写进**临时目录**再 `subprocess` 跑时，`sys.path[0]` 是那个临时目录，**`sys.path.insert` 救不了子进程**（改不到它的 `sys.path`），而 `cwd=backend` 也**没用**（Python 从不把 cwd 放进 `sys.path`）。唯一解是在子进程 env 里显式 `"PYTHONPATH": str(BACKEND)`。`smoke_be07.py` 就是这么漏的 —— 报错是 `ModuleNotFoundError: No module named 'app'`，看着像环境问题，其实是脚本自己少传了一个变量。
- **⚠️ 沙箱会把「应用自己删文件」当成工具删文件拦下来**（WorkBuddy 环境专有，非代码缺陷）。本机 `PYTHONPATH` 被注入了 `.../cli/vendor/shim`，里面 `sitecustomize.py` 会 hook `unlink/remove/rmtree`；一旦**本轮**已有过一次「批量删除拒绝」记录（阈值 50 个文件，烟测清理浏览器 profile 目录就会触发），之后**同轮内所有删除一律拒绝**，而且拒绝方式是 `raise SystemExit(1)` —— **进程直接死**。
  - 症状：`spawn` 出来的 uvicorn **一行日志都不出**就没了，或死在 `check_backup_dir` 的 `probe.unlink()`（`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`）。因为 `SystemExit` 继承自 `BaseException`，应用里 `except OSError` **兜不住**，也不该为了兜它去写 `except BaseException`。
  - 解法：跑真机烟测时用 **`env -u PYTHONPATH <cmd>`** 起进程（子进程继承的就是干净 env），**不要改烟测脚本去适配沙箱** —— 那是把环境问题烧进代码。
- **MSYS/Git-Bash 缺 `PATHEXT` 会让 Windows 程序找不到 exe**：`where xxx` 失败但直接执行正常；凡依赖 `where` 定位可执行文件的工具（`flutter_tools` 等）都会崩。
- **`nohup cmd &` 起的后台进程会随 shell 退出被带走** —— 想验证「服务能否真启动」，写**自包含 Python 脚本**（起子进程 → 轮询就绪 → 断言 → 收尸），别依赖 shell 后台任务。
- **`flutter test` 默认会掐掉真实 HTTP**：`TestWidgetsFlutterBinding` 装了一个全局 `HttpOverrides`，
  把**任何**真请求吞成 `400 + 空响应体`（框架防止单测偷偷打网络的保护）。
  症状极具迷惑性：`ApiClient` 走到 `_unwrap` 判 `payload is! Map` → 抛「收到的数据和预期不一样」，
  若用例写了「后端没起就 skip」，整层会**「全绿，其实一个真请求都没发出去」**。
  解法：真机联调文件 `setUpAll` 里 `HttpOverrides.global = null;`（要 `import 'dart:io'`）。
- **「全部跳过」不能算通过**：自动化验收脚本里，skip 是**伪装成绿色的失败**。
  解析 `flutter test` 输出里的 `+N` / `~N`，`~N > 0` 直接判失败，并要求通过数 ≥ 期望下限
  （否则「测试文件没被收集」也是绿的）。
- **就绪探测要按「契约字段」写，不要按「当前实现」写**：
  本次探测条件写的是 `data["service"]`，而当时后端桩只回 `{"pong": true}` →
  服务**早就就绪**却被判超时，白等 60 秒。按实现写探测条件，实现一变就静默失效。
- **子进程清理要「terminate + wait」，必要时 kill 兜底**：只 `terminate()` 不 `wait()`，
  会留下残留 uvicorn 占着端口，下一轮脚本一开就报「端口被占用」，且报错指向错误的方向。
  脚本收尾还应**再查一次端口**并提示残留 PID。
- **别用裸 `ApiClient` 断言「已落库」**：解包 `{code,message,data}` 是 client 的事，
  写本地存储是 `AuthController` 的事。真机联调若只验契约字段就走裸 client，
  要验「token 往返 + 落库 + 启动校验」必须走生产路径（`ProviderContainer` + `AuthController`）。
- **「构建 / 类型检查通过」≠「页面能渲染」** —— 前端交付**必须真跑浏览器**。
  - 要**真交互**（填表、点按钮）用 CDP；`--dump-dom` 只能看静态结果。
  - **Node 22 内置 `WebSocket`（undici）驱动不了 Chrome/Edge CDP**：握手成功但**一个回帧都收不到**。解法：用 Chrome 官方 `--remote-debugging-pipe`（fd3 写 / fd4 读，一行 JSON + NUL），**零依赖**，别为此装 `ws` 包。
  - 导航瞬间 `Runtime.evaluate` 会因执行上下文销毁报错 → 求值封装要「失败即视为未就绪、继续轮询」。

### 管理端联调（WEB-02 新增）

- **后端给的「可直接用的 URL」和前端 `baseURL` 会叠加，务必验一次真请求。**
  本次 `error_report_url` 后端返回 `/api/import/report/{token}`（**自带 `/api`**），
  前端 axios 实例 `baseURL='/api'` → 拼成 `/api/api/import/report/{token}` → **404**。
  这类缺陷的特征是「**代码看着完全对**」（两边各自都符合自己的契约），
  所以**只断言"接口返回了某个字段"是抓不到的**，必须真的把文件下下来看魔数。
  通用做法：给「后端返回的路径」加一层 `toApiPath()` 归一化 —— **剥掉前导 `/api`**，
  `http(s)://` 开头的绝对地址**原样保留**（以后 API 换域名也用得上）。
- **烟测的"用例数下限"要跟着用例增删同步改**（`MIN_CASES`）。加了 `W13` 却忘了把下限从 12 提到 13，
  等于自己给自己留了一个「用例被静默跳过」的口子 —— 防假绿的机制本身失效了。
- **进程收尾要连带收回「子进程树」**：Windows 上 `spawn` 出的 uvicorn 被 `taskkill /T /F` 之外的方式结束，
  很容易留下一个**还在占着端口的孤儿进程**。本次残留的那个不但占了 HTTP 8813，还占着 **UDP 9527**，
  直接导致后面全量回归里 `test_u2_udp_real_roundtrip` 与 `test_startup_checks_cover_four_items` **两条红**
  （报 `[WinError 10048]`）。**看到 UDP 端口类的失败，先 `netstat -ano -p UDP` 查孤儿进程，再怀疑代码。**

### Flutter 组件测试 / 客户端联调（APP-02 新增）

- **客户端的「请求体构造」必须由真机烟测覆盖，单测覆盖不了。**
  假 HTTP 适配器**只负责回一段 JSON，不校验请求 schema**，所以「字段名拼错」和
  「值不在后端枚举里」这两类错误在单测里**看起来完全正常**。
  本次 `mode:'recite'`（后端只收 `cn2en/en2cn/mixed`）就是这么漏过去的：
  94 个单测全绿，语文练习实际**一条都发不出去**。
  写法：烟测里**调生产代码的请求体构造函数**（`PracticeConfig.toRequest()`），
  不要手写 JSON —— 手写就只能验自己抄得对不对。
- **别用 `initialRoute: '/home'` 挂被测页**：Flutter 会把 initialRoute 按 `/`
  **逐级拆开**，连 `/` 上的启动页一起 build。启动页的异步探活失败会
  `pushReplacement` 到服务发现页，**把栈顶的被测页顶掉**，还留下真 UDP 定时器让
  `pumpAndSettle` 永远等不完（表现为 `pumpAndSettle timed out`，离根因十万八千里）。
  正确做法：`home: 被测页` + `routes: AppRouter.routes..remove(AppRouter.initialRoute)`，
  并把 `broadcastFinderProvider` 换成不发 UDP 的假件。
- **默认视口 800×600 + `ListView` 懒加载 = 下方选项根本不会被构造**。
  症状是「`find.text('15 秒/题')` 找不到」，读起来像"文案写错了"。
  `tester.view.physicalSize = Size(1200, 3600)` + `addTearDown(tester.view.reset)`
  比每处 `scrollUntilVisible` 省事，也更接近真机（手机屏幕本来就长）。
- **断言「按钮是否可点」别用 `Semantics.enabled`**：祖先 `enabled=false` 时取不到值
  （报 `Expected: false, Actual: <null>`），会让人以为控件坏了。
  直接读组件自己的 `onPressed`：`tester.widget<AppButton>(find.widgetWithText(...)).onPressed`
  再断言 `isNull` / `isNotNull`。
- **组件里声明了 `tooltip` 参数 ≠ 存在 `Tooltip`**：只把它喂给 `Semantics(label:)` 时，
  `find.byTooltip('减少')` 是**找不到**的（找的是真 `Tooltip` 组件）。
  两选一：真包一层 `Tooltip(excludeFromSemantics: true, ...)`（顺带低龄学生长按能看提示），
  或把断言换成 `find.byIcon(...)`。
- **测试替身里「私有字段 + 公开具名形参」合并不了**：具名形参不允许以下划线开头，
  所以 `prefer_initializing_formals` 会报 info 却无法照它改。
  直接**把字段公开**（`this.units` 等），别用 `// ignore:` 糊过去。
- **契约断言的顺序：先核实现，再核文档。** 文档可能**自己前后矛盾**（本次 §8.6 与
  §8.7/§9.4 对 `total_chars` 的定义打了架）。此时正确做法是
  **钉住实现现状 + 在断言里写清「这条变红意味着什么」**，
  而不是按文档的某一半去改实现 —— 那是越权改别人的包。
- **真机烟测脚本顺手把「造数」也做了**：`smoke_app02.py` 走**真 Excel 两步式导入**
  造英语词条 + 语文课文，于是每跑一次烟测就**顺带回归了 BE-03/BE-05 的导入链路**，
  而且不需要手工准备数据、不污染正式库。
  - SPA 的 `readyState` 会先 `complete`，要再等「`#app` 有子元素」才算真的挂载。

- **`flutter test` 绝不能传 `-d`**：`-d <device>` 是 `flutter run` 的参数；`flutter test -d none`
  会让 dart 进程 **0 CPU 空转、永不结束**（本次实际挂了 **42 分钟**没退出，还是靠
  「没有 `flutter_tester` 子进程 + CPU 不涨 + 无新输出」才判出来的）。
  排查口径：**先看进程再怀疑代码** —— `Get-Process dart,flutter_tester` + 采样两次 CPU。
- **烟测脚本「整轮被异常中断」也会打印 PASS（假绿，必须修）**：
  统计函数只算「已记录用例里有没有失败」，中断发生在最后一条之前时，先前用例全 `ok`
  → 打印 `RESULT 7/7 PASS`（**退出码其实是 1**）。
  修法：`catch` 里把「中断」本身补成一条失败用例（`ABORT_ERROR` 标记），让**结论行与事实一致**；
  退出码照旧保留。教训：**只看统计行、不看退出码的人非常多**，结论行绝不能骗人。
- **`StreamSubscription.cancel()` 不能挂在关键路径上 `await`**：
  受控时钟（`tester.pump`）下 `Stream.empty().listen().cancel()` **永不完成** ——
  页面「结束并结算」会**静默卡死，连异常都抛不出来**（先表现为"点了没反应"）。
  已改为**不 await**（`unawaited`），并把这条 SDK 约束固化成特征化测试
  `test/test_app04_teardown_cancel_test.dart`（哪天行为变了会变红，提示可重新评估）。
- **`Navigator.push` 在 `await` 之后发出时，同一帧 `pump(Duration)` 只走动画起点**，
  新页面还没上屏 → 断言「新页面文案」必然找不到。写成
  `pump()` → `pump(Duration)` → `pumpAndSettle()` 才稳。
- **早期包留下的「还没落地」时序断言，落地时必须回头改**：APP-01/02 写过
  「练习页 / 错题本还没落地」的期望，APP-03/04/05 落地后必然变红（本次一次改了 4 处）。
  不改的后果不是"红一条"，而是**"永远红一条，大家就习惯了"** —— 等于把红灯变噪音。
- **后端返回「数组」而客户端按「数字」解析，是假适配器测不出的形状错配**（见 §八 #66）：
  `int.tryParse("[0, 1, 2, 3]")` 静默返回 null → 字段恒 0，全绿。
  凡「响应可能有多种形状」的字段，解析都要写形状分支，并用**真机断言**钉住。
- **WS 那层也能进烟测，且很值**：`task_type=recite` 的 `partial` 帧真的会推进服务端 `pos`
  （`session_manager._recite_feed`）。要点：① 用 `ASR_CONFIG_PATH` 指一份临时
  `provider: mock` 的 yaml（仓库里的 `asr.yaml` 是 `aliyun` + 空 key，不改必挂）；
  ② mock 的 `by_task.recite.final_text` 要**设成课文里的字**，partials 才能推进引擎
  （否则断言退化成"连接成功"）；③ 断言 `started.provider == 'mock'`，防止配置没生效却"通过"。

### ASR / 语音预研

- **判分场景要测「负样本忠实度」** —— 录**故意念错**的音频，看模型会不会把错读「纠正」成正确词。本次正样本第一名（95%）的模型，负样本 4 条中 2 条被掩盖，只能弃用。
- **模型市场的展示名 ≠ 调用 model id** —— 先拉 `/compatible-mode/v1/models` 核对，或直接试探调用。
- **TTS 音频不能盲信**：用它评 ASR 前**必须先做音频质检**（第二个模型独立听，或用时长粗筛），否则会把 TTS 的错误算到 ASR 头上（本次三字母短词约 16% 跑偏）。TTS 输出 wav 的 data chunk 大小是占位值（`0x7FFFFFFD`），算时长要按文件实际大小。
- **先把判定门限写在测试之前**，避免结果出来后按情绪调标准。
