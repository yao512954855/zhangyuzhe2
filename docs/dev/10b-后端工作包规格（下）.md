### 核心：对齐算法怎么实现

这是**全项目技术难度最高**的一块。契约给了 `ReciteEngine` 的签名，这里说清怎么把它做出来。

**输入准备（初始化时）**

```
从 texts 读出 content_plain（纯汉字序列，逗号分隔或直接串）与 content_pinyin（空格分隔拼音）
按 recite_scope（段落索引数组）反查字符区间，截取目标：
  target_chars  = content_plain 在区间内的汉字数组
  target_pinyin = content_pinyin 在区间内的拼音数组
两者长度必然相等（导入时已校验）
```

**关键设计：为什么在拼音层对齐**

汉字识别结果会带同音字错误（的/地/得、在/再、他/她/它）。若在汉字层比对，这些会全被算成"背错"。在**拼音层**比对，同音字自然通过，只有真正的读音错才算错。这是需求 §6.3 的明确要求。

**`feed(partial_text)` 的处理流程**

1. **接收的是累计文本**：ASR 的 `partial` 是"到目前为止识别出的全文"，不是增量。引擎内部记录 `consumed_len`，每次取 `partial_text[consumed_len:]` 作为新增片段，避免重复处理已消费内容。
2. 新增片段转拼音（`pinyin_service`），得到 `in_seq`。
3. **窗口内局部最优对齐**：在 `target_pinyin[pos : pos + N]`（N=20，可配）内，枚举对齐起点 `s`，用编辑距离把 `in_seq` 与 `target_pinyin[s : s + len(in_seq)]` 对齐，取「编辑距离最小、匹配字符数最多」的位置作为最佳匹配。
4. **匹配率判定**：`匹配率 = 匹配字符数 / len(in_seq)`。
   - `≥ noise_threshold`（默认 0.3 是"噪声上限"，实际用 `1 - 0.3 = 0.7`？——**注意**：需求写的 0.3 是"匹配率低于 0.3 判为噪声"，所以阈值语义是**匹配率 < 0.3 → 噪声**。实现时读 settings `asr_noise_threshold=0.3`，直接用 `匹配率 < threshold` 判噪声）
   - 噪声：`is_noise=True`，`pos` 不推进，不记错。
   - 正常：推进 `pos` 到匹配结束位置之后；**跳过的目标字符记入 `missed_chars`**（漏字）。
5. **容错规则**（需求 §6.3）：
   - 同音字：拼音相同即算匹配。
   - 漏字：允许跳过并记录，不阻断。
   - **连续漏字 ≥ 5**（settings `miss_streak_hint`）：视为卡壳，触发自动提示。
   - 回读重复（学生重复已背内容）：**不回退 `pos`**，仅记录，不判错。
   - 多字：忽略多余内容。
6. 返回 `FeedResult{pos, newly_matched, is_noise}`。

**`check_auto_hint(silence_ms)`**

- 静音计时由调用方（BE-06 的会话循环）维护并传入。
- 触发条件二选一：`silence_ms >= settings.silence_hint_ms`（默认 8000）**或** 连续漏字达到 `miss_streak_hint`（默认 5）。
- **同一位置不重复触发**：内部记录 `last_hint_pos`，位置变了才允许再触发。
- 返回应触发的档位（`1..3`，逐次递增，到 3 封顶），无触发返回 `None`。

**`apply_hint(level, trigger_by)`**

| 档位 | 展示内容 |
|---|---|
| 1 | 后面还有几个字（`["_"] * 剩余字数`，前端渲染为一排空框） |
| 2 | 下一个字的首字（中文给首字；本题是中文） |
| 3 | 下一个字的完整答案 |

每次调用写一条 `recitation_events`（`event_type='hint'`，含 `hint_level`、`trigger_by`、`pos`、`elapsed_ms`）。

**`finish(reason)` 结算**

按需求 §6.4 与 settings 权重：
```
覆盖比例 cover = matched_chars / total_chars
正确率 accuracy = 1 - len(missed_chars) / total_chars
提示惩罚 penalty = min(100, 提示总次数 × 5) / 100
score = 100 × (0.6×cover + 0.25×accuracy) - 15×提示总次数   ← 见下方说明
```

> **注意权重实现口径**：需求 §6.4 写的是「覆盖 60% + 正确率 25% + 提示惩罚 15%（每次提示扣 5 分，扣完为止）」。实现取：
> `score = 60×cover + 25×accuracy + 15×max(0, 1 - 提示总次数×0.05)`，下限 0，上限 100。
> 这个公式与"每次扣 5 分、扣完为止"等价（15 分额度内每次扣 5 分，3 次扣完），且三部分权重之和为 100。**以本公式为准**，写进 `settings` 注释避免歧义。

评级：`≥90 优秀`、`75–89 良好`、`60–74 合格`、`<60 待加强`。

### 接口

| # | 接口 | 要求 |
|---|---|---|
| F1 | `POST /api/recitations` | 入参 `session_id`、`text_id`、`scope`；返回 `recitation_id`、`total_chars`、`char_count_per_paragraph`；**不下发拼音、不下发正文**（正文已在 8.7 拿过） |
| F2 | `POST /api/recitations/{id}/events` | 可选批量上报事件流；**一期可只写结算**，但接口要存在，供 App 断线补报 |
| F3 | `POST /api/recitations/{id}/settle` | 入参含 `transcript`/`matched_chars`/`missed_chars`/`hint_count`/`restart_count`/`duration_ms`/`first_voice_ms`/`finish_reason`；**服务端重新校验一致性**（用 `transcript` 重跑一次对齐，以服务端结果为准，客户端数据仅参考）；写 `recitations`；返回 `covered_ratio`/`score`/`grade`/`missed_detail` |
| F4 | 事件批量写入 | `recitation_events` 在背诵结束时**一次性批量提交**，不在流式过程中逐条写库 |
| F5 | 服务端重算 | `settle` 必须忽略客户端上报的 `matched_chars`（防刷分），以服务端对齐结果计算 |

**关于实时性**：一次背诵过程中，`feed` 会被高频调用（每次 partial 一次）。所有状态放在**内存对象**里（`ReciteEngine` 实例按 `recitation_id` 缓存），**不在过程中写库**，只在 `settle` 时落库。进程重启会丢进行中的背诵——可接受（学生重背即可）。

### 关键实现要点

- **Provider 必须异步**：WebSocket 与云端都是长连接 IO，用 `asyncio` + `websockets`/`aiohttp`，不要在事件循环里做阻塞调用。
- 音频分片是**二进制帧**，与 JSON 控制帧混在同一连接上——服务端要区分 `bytes` 与 `str` 消息。
- 阿里返回的是**分片结果**，拼接语义要在 Provider 内处理成「累计文本」再回调，供 `ReciteEngine.feed` 直接使用。
- 主备切换要**无感**：切换后当前任务的音频不能回放（已消费），只能对后续分片生效；必要时直接判本次失败并让客户端重录。
- 限流与队列用 `asyncio.Semaphore` + 计数，不要在 WS 里 sleep 等待。
- **MockProvider 是并行开发的关键**：它让 APP-03/APP-04 在没有云账号时也能联调完整流程。

## WP-BE-07 统计看板与申诉复核

| 项 | 内容 |

### 目标

管理者能看班级掌握度、单元难词、学生个人报告，能复核申诉，能看语音用量。

### 独占文件清单

backend/app/api/appeals.py

### 功能点详述

| # | 接口 | 要求 |
|---|---|---|
| F1 | `GET /api/stats/class/{id}` | 班级概览：人数、今日活跃、完成率、平均正确率、平均用时、趋势（按天）、错题 Top N；`date_from`/`date_to` 默认近 7 天 |
| F2 | `GET /api/stats/unit/{id}` | 单元掌握度：词条数、学生数、正确率、已掌握比例、未完成学生列表、难词榜（正确率升序）。⚠️ **口径（2026-09-25 裁决 A，§八 #82）**：`unfinished_students` = **练过该单元但未完成**的学生；**学生宇宙 = 练过该单元的人**（`COUNT(DISTINCT answers.student_id)`），**从未练过的学生不在其中** |
| F3 | `GET /api/stats/student/{id}` | 个人报告：练习天数、场次数、正确率、已掌握词数、连续天数、最近场次、背诵记录、错词 |
| F4 | `GET /api/appeals` | 待复核列表；`status` 支持 `pending`/`upheld`/`rejected`；`audio_available` 一期恒为 `false`（不存音频） |
| F5 | `POST /api/appeals/{id}/review` | 复核：`upheld`/`rejected` + `remark`；**不改原对错判定**；写 `audit_logs` |
| F6 | 正确率统一口径 | 抽出 `calc_accuracy()` 单一函数：分母 = 总数 − `empty` 数，分子 = `exact + loose + fuzzy`；**全项目唯一实现** |
| F7 | 视图优先 | 能用 `v_word_error_ranking` / `v_student_unit_progress` / `v_class_today_activity` 的，不重复写聚合 SQL |
| F8 | ASR 用量统计 | `GET /api/stats/asr`：按天/厂商返回调用次数、音频总时长、平均延迟、失败率；数据来自 `asr_daily_stats` 与 `asr_logs` |
| F9 | 日聚合任务 | 每日 03:00 把 90 天前的 `asr_logs` 明细聚合进 `asr_daily_stats` 后删除明细；**保留最近 90 天明细** |
| F10 | 审计日志查询 | `GET /api/audit-logs`（P3）：分页 + 按用户/动作/时间筛 |
| F11 | 数据导出 | `GET /api/stats/export`（P3）：导出班级或学生成绩为 xlsx |

### 关键实现要点

- 统计 SQL **必须走索引**；`answers` 表上 `idx_answers_stu_created`、`idx_answers_stu_word` 是给这类查询用的。
- 班级概览的"趋势"按天聚合，注意服务端时间是 UTC，**按 Asia/Shanghai 切天**（用 SQLite 的 `datetime(created_at, '+8 hours')`）。
- `mastered_ratio` 走 `word_mastery`，不要实时扫 `answers`。
- 完成率口径需明确定义并写进文档注释：`完成率 = 至少练过 1 次的词条数 / 单元词条总数`（一期按词条维度，不按学生维度）。
- 申诉列表只返回**尚未复核**的为首屏默认。

## WP-BE-08 服务发现与运维

| 项 | 内容 |

| 优先级 | **P0** |

### 目标

解决「服务器 IP 经常变，用户不懂网络」这个核心运维痛点，并把备份、自启、告警落地。

### 独占文件清单

```
backend/app/api/discovery.py
backend/app/services/discovery/__init__.py
backend/app/services/discovery/udp_responder.py   # UDP 广播应答
backend/app/services/discovery/netinfo.py         # 本机地址枚举、推荐地址
backend/app/services/backup_service.py
backend/app/tasks/scheduler.py                    # 定时任务（备份/聚合）

ops/README.md                                     # 部署手册

backend/app/tests/test_be08_backup.py
```

### 功能点详述

| # | 功能 | 要求 |
|---|---|---|
| F1 | `GET /api/ping` | 免鉴权；返回 `service`/`version`/`server_name`/`time`；**必须极轻量**（不查库，或只查一次缓存版本号） |
| F2 | UDP 广播应答 | 监听 UDP `9527`；收到 `{"magic":"BJSYS_DISCOVER","v":1}` → 单播回 `BJSYS_HERE` + `host`/`port`/`server_name`/`need_auth`；**只响应局域网私有网段**（校验来源 IP 属于 `10.x`/`172.16-31.x`/`192.168.x`），拒绝公网；应答不含任何敏感信息 |
| F3 | `GET /api/server/info` | 枚举本机所有网卡地址，标出 `recommended`（优先有线以太网、其次 WLAN）；返回 `current_url`、`qr_content`（格式 `bjsys://{ip}:{port}`）、`broadcast_enabled`、`last_ip_change_at` |
| F4 | IP 变化检测 | 定时（60s）比对当前地址与上次记录；变化时更新 `last_ip_change_at` 并写审计，供管理端提示 |
| F5 | 二维码内容 | 服务端只产出 `qr_content` 字符串；**实际二维码由管理端前端渲染**（减少服务端依赖） |
| F6 | 备份服务 | 每日 02:00 执行 `VACUUM INTO` 到 `BACKUP_DIR/app_YYYYMMDD.db`；完成后跑 `PRAGMA integrity_check`；结果写 `audit_logs`；**保留 30 天**，超期删除最旧；失败时记录并（可选）告警 |
| F7 | 手动备份 | `POST /api/maintenance/backup`（admin）：立即备份，返回文件路径与校验结果 |
| F8 | 恢复说明 | `ops/README.md` 写清恢复步骤（停服 → 替换 db → 删 wal/shm → 启服），**不要提供自动恢复接口**（风险太高） |
| F9 | 定时任务调度 | 用轻量调度（APScheduler 或自写 `asyncio` 循环）；统一入口，承载备份与 ASR 日聚合 |
| F10 | Windows 服务化 | `ops/install_service.ps1` 用 NSSM 或 `sc.exe` 注册服务；开机自启；日志目录可配 |
| F11 | 部署手册 | `ops/README.md` 必须包含：端口占用清单、固定 IP 建议（路由器 MAC 绑定）、防火墙放行（8810/tcp、9527/udp）、备份与恢复、常见故障排查 |
| F12 | 降级告警标记 | 维护一个内存状态 `degraded_reasons`（如「外网中断 → 全站键盘模式」）；`GET /api/server/info` 或 `/api/health` 中暴露，管理端可显示横幅 |
| F13 | 启动自检 | 启动时检查：DB 可写、迁移版本、备份目录可写、UDP 端口可绑；任一失败在日志中明确告警（不阻止启动，除 DB 不可用） |
