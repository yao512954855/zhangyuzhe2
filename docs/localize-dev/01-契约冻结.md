## §1 三模式语义（逐能力行为矩阵）

### §1.1 TTS（听写播报，入口 `tts_service.synthesize(text, lang) -> bytes`）

| 模式 | 行为 |
|---|---|
| `local` | 只走本地引擎；引擎不可用/失败 → `BizError(50006)`，**不得**触碰云端 |
| `hybrid` | 先本地；本地抛任何异常/产物非法 → 自动走云端 `_synthesize_remote`；云端也失败 → `BizError(50005)` |
| `cloud` | 与现状完全一致：只走云端 `_synthesize_remote` |

缓存：磁盘缓存键从 `md5(f"{lang}|{text}")` 改为 `md5(f"{engine}\|{lang}|{text}")`，`engine ∈ {"local","cloud"}`（不同引擎产物分开放，互不命中）；缓存目录不变 `data/tts_cache/`。

### §1.2 OCR（拍照批改，入口 `dictation_service.grade_handwriting(...)`）

| 模式 | 行为 |
|---|---|
| `local` | 只走 `_LocalOcrClient`；不可用/失败 → `BizError(20005)`（沿用 OCR_GRADE_FAILED，不新增码） |
| `hybrid` | 先本地；本地**抛异常**或**识别出有效块数 == 0** → 自动走云端 `_OcrClient`；云端也失败 → 20005 |
| `cloud` | 现状：只走云端 |

**本地客户端输出必须适配阿里云同构 map**（这是解析层零改动的关键）：
`_parse_blocks()`（dictation_service.py:176）认的字段 = `Data.prism_wordsInfo` 列表，每块 `{"word": str, "x": int, "y": int, "prob": int(0~100)}`；全文 = `Data.content`。
`_LocalOcrClient.recognize(image_bytes)` 返回：

```python
{"Data": json.dumps({
    "content": 全文（按阅读顺序拼块）,
    "prism_wordsInfo": [{"word": ..., "x": ..., "y": ..., "prob": ...}, ...]
}, ensure_ascii=False)}
```

注意 `Data` 是 **JSON 字符串**（`grade_handwriting` 与 `_parse_blocks` 都有 `json.loads` 二次解析逻辑，兼容 str）。`x/y` 取 RapidOCR 检测框**左上角**坐标（int）；`prob = round(score * 100)`。

### §1.3 ASR（语音识别，入口 `session_manager` 的 `ASRRouter`）

模式映射为 **provider 顺序**（复用 `ASRRouter` 既有主备语义：建连失败切下一个 + 连续 3 次失败粘性切换）：

| 模式 | order（按序尝试） |
|---|---|
| `local` | `["local"]`（无备） |
| `hybrid` | `["local", <asr.yaml 原主厂商>]`（回落「云端」= asr.yaml 配置的主厂商，生产环境即 aliyun；测试环境为 mock） |
| `cloud` | 原样使用 asr.yaml 的 provider/backup_provider（现状，不覆盖） |

规则（写死）：
1. 映射发生在 `AsrSession.__init__`（session_manager.py 建 `ASRRouter` 处）：**复制** raw dict 后覆盖 `raw["provider"]`/`raw["backup_provider"]`，不修改 `load_asr_raw()` 的原始返回；
   （v1.0.1 修订：hybrid 的回落顺位从写死 "aliyun" 一般化为「asr.yaml 原主厂商」——原写法在测试环境（primary=mock）会把云端顺位指向未配置 key 的 aliyun 导致建连双重失败；语义不变，生产行为一致。）
2. 模式在**会话建立时**读取一次，进行中的会话不切换（新会话生效）；
3. `asr_logs.provider` 记录实际用上的（`ASRRouter.used_provider`，现状行为）；
4. 本地 provider 建连失败（模型未下载/加载异常）→ ASRRouter 自动落下一个顺位，无需新逻辑。

**（v1.0.3 修订，2026-10-13，姚工确认：简化版 spell_zh2en 判格触发时机）**

原设计「letter 逐格判定只在 WS `end` 后触发」与 App 现状矛盾：简化版 App「看中文背英文」模式**没有 end 入口**（「我说完了」按钮只在 en2zh 模式），真机实测判格永不触发 → 字母格永远不亮、页面表现为卡死（后端日志佐证：8 分钟音频零 partial 变化、零 letter、零 final）。修订为：

- LocalProvider 的 Vosk 拼读通道新增 **utterance（语句级结果）通道**：① `AcceptWaveform` 返回语句边界时取 `Result()`；② **服务端静音收口**——partial 停止变化 ≥ `SILENCE_FLUSH_MS`（700ms）主动取 `Result()`。两条路径都即时转给网关 `_spell_feed` 逐格判定并下发 `letter`，**不等 end**。
  （实测依据：22 条 qa spell 音频 `AcceptWaveform` 边界触发 **0 次**——音频为整词一气念成、尾静音不足；真人「念一个字母停一下」由静音收口路径保障。）
- `end` / `close` 退化为兜底：close 的残余文本也经 utterance 通道判格；`_on_end` 的 spell 分支**不再重复判格**（同一文本重复跑会把字母对着已推进的游标错位重判）。
- App 行为不变（已装版本直接生效）：念对一个字母格子即亮，填满自动下一题；「结束并结算」仍是整轮收口。
- 对 `recite`/`word`/`en2zh` 等其他链路零影响：utterance 仅 LocalProvider 的 spell 通道产生，其他 Provider 不注册/不触发。

### §1.4 拼写检查

compare_service 本来就是本地精确匹配，**不参与模式**，任何模式下行为不变。

## §2 配置源与优先级

```
解析函数 resolve_mode(cap: str) -> "local" | "hybrid" | "cloud"   # cap ∈ {"tts","ocr","asr"}
1. 读环境变量 CAP_TTS / CAP_OCR / CAP_ASR（非空且合法 → 直接生效 = 部署级锁定）
2. 否则读 settings 表键 capability_mode（管理端按钮写的）
3. 都没有 → 默认 "hybrid"
非法值（如 "auto"）→ 按 hybrid 处理并 log warning（不准启动失败）
```

- settings 表新增种子（走 `004_capability.sql`，`INSERT OR IGNORE`）：
  `('capability_mode', 'hybrid', 'string', 'AI能力模式：local/hybrid/cloud，管理端可改')`
- `.env` 新增三个**可选**键 `CAP_TTS` / `CAP_OCR` / `CAP_ASR`（注释写明「留空=跟随管理端按钮」）。`.env` 不入库的原则不变（模板示例写进 40-集成验收 的部署说明）。
- 环境变量读取优先 `os.environ`，回落解析 `backend/.env`（**照抄 `dictation_service._read_ocr_env` 的实现套路**，但抽成公共函数，见 10-后端-能力框架 §3）。
- 每次调用**现读**（不准进程内缓存模式值）：TTS/OCR 每请求读一次；ASR 每会话读一次（§1.3）。这保证管理端改完立即生效。
- 锁定语义：`.env` 键非空的能力，管理端按钮对它**不生效**；API 返回里该能力 `locked: true`，管理端显示「已被部署配置锁定」。

## §3 引擎技术栈与模型清单（写死）

统一底座 **onnxruntime**（sherpa-onnx 与 rapidocr-onnxruntime 共享依赖）。全部 CPU、全平台有 wheel。模型放 `backend/models/`：

| 用途 | 包 | 模型 | 体积 | 下载源（按序尝试） |
|---|---|---|---|---|
| TTS 英文 | sherpa-onnx | `vits-piper-en_US-amy-medium`（Piper 模型） | ~63MB | ①GitHub k2-fsa/sherpa-onnx releases 直连 ②`https://ghproxy.cn/` 前缀 |
| TTS 中文 | sherpa-onnx | 首选 `vits-melo-tts-zh_en`（中英混合）；备选 `kokoro-multi-lang-v1_1`、`vits-zh-hf-fanchen-C` | 163MB~310MB | 同上 |
| OCR | rapidocr-onnxruntime | 包内置 PP-OCRv4 mobile（det+rec），**无需单独下载** | ~15MB | pip 即可 |
| ASR 字母拼读(zh2en) | vosk | `vosk-model-small-en-us-0.15` | 40MB | `https://alphacephei.com/vosk/models`（国内可达；失败用 `https://ghproxy.cn/https://github.com/alphacep/vosk-api/...` 不适用时改用 modelscope 镜像并上报实际 URL） |
| ASR 中文(en2zh/背诵) | sherpa-onnx | **契约修订 v1.0.2（2026-10-13）**：首选 `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2024-07-17`（SenseVoice small int8，离线 16k，带 ITN，model.int8.onnx 228MB）。原首选 `sherpa-onnx-streaming-zipformer-bilingual-zh-en-2023-02-20` 预研双门 FAIL（孤立英文词 0.04、干净中文短词 1/3，云端 fun-asr 对同批音频 6/6 证明音频无问题）→ 换型 | ~230MB | 同 sherpa releases |

模型选型**验收驱动的备选规则**（不算歧义）：首选模型下载失败或验收不达标时，按上表备选顺序尝试；全都失败 → 停下上报，不准私自换表外模型。

下载脚本 `backend/scripts/download_models.py`（幂等：已存在且大小>1MB 跳过；`--only tts|asr` 可选）。

## §5 接口冻结（对外 API 一律不变 + 新增两个管理接口）

**不变的**（响应字节级兼容，App 零改动）：
- `POST /api/tts` → `audio/wav` 二进制；失败 200+envelope（现有语义）。
- `POST /api/dictation/grade` → 现有 envelope（`results`/`ocr_content`）。
- `/ws/asr` 全部消息类型与语义。

**新增**（批次 A 交付，批次 D 消费）：
```
GET /api/capabilities
→ ok({"mode": "hybrid",
       "engines": {
         "tts": {"mode": "hybrid", "locked": false, "local_ready": true,
                  "local_detail": "piper en_US-amy-medium + melo-zh_en"},
         "ocr": {...同构...},
         "asr": {...同构...}}})
PUT /api/capabilities/mode   {"mode": "local"|"hybrid"|"cloud"}
→ ok(...)  写 settings.capability_mode；mode 非法 → PARAM_INVALID(10001)
```
`local_ready` 判定 = 模型文件齐全 + 包可 import（**轻量探活**：只查文件与 import，不真合成；结果可缓存 60s）。`mode` 字段 = 该能力 resolve 后的实际生效模式；`locked` = 对应 `.env` 键非空。

## §6 懒加载与并发

- 本地引擎模型**进程内单例** + `threading.Lock` 双检锁；首次请求加载（TTS/OCR 每引擎约 0.5~3s，一次性）。
- sherpa TTS/ASR、Vosk：Model 全局单例，会话/请求级对象按需新建（Vosk Recognizer、sherpa stream）。
- 加载失败 → 该次请求按 §1 矩阵走 fallback；并置 `local_ready=false`（60s 内不再反复重试加载，防雪崩）。

## §7 验收门（不达标不准上线该能力）

1. **OCR 手写门**：用手写样张（qa 目录现有样张 + 姚工提供，≥10 张，每张 3~6 个单词）实测本地 OCR：**逐词判分准确率 ≥ 8/10 张**（以 `grade_handwriting` 的 results 口径算）。脚本 `backend/scripts/_ocr_local_probe.py`（产物：每张图的 results 摘要 + 汇总通过/不通过结论到 stdout）。
2. **ASR 预研门**：`backend/scripts/_asr_local_probe.py` 用 `qa/audio/`（71 个 wav）：
   - `*__spell.wav`（逐字母）：识别序列对 target 的**字母命中率 ≥ 90%**；
   - `*__whole.wav`（整词/短句）：归一化命中 ≥ 80%；
   两项同时达标才允许把 LocalProvider 接进 PROVIDERS；不达标 → 停下上报实测数据，等裁决。
3. TTS 门：本机合成「apple / good morning / 苹果 / 你好吗」4 条 wav，人耳可辨识、非空 RIFF（脚本探针即可，无主观评分线）。
