# 20 - 批次D · 管理端「AI 能力模式」切换页

> 依赖：批次 A 的接口冻结（01 §5）。可与 B/C 并行。
> 消费接口：`GET /api/capabilities`、`PUT /api/capabilities/mode`。

## 1. 新增 `admin-web/src/api/capabilities.ts`

照 `admin-web/src/api/server.ts` 的结构与命名风格：

```ts
export interface EngineStatus {
  mode: 'local' | 'hybrid' | 'cloud'   // 该能力实际生效模式
  locked: boolean                       // .env 部署级锁定
  local_ready: boolean
  local_detail: string
}
export interface Capabilities {
  mode: 'local' | 'hybrid' | 'cloud'    // 全局设置值
  engines: { tts: EngineStatus; ocr: EngineStatus; asr: EngineStatus }
}
export const getCapabilities = () => api.get<Capabilities>('/api/capabilities')
export const setMode = (mode: Capabilities['mode']) =>
  api.put<Capabilities>('/api/capabilities/mode', { mode })
```

- 若 `client.ts` 的 `api` 没有 `put`：按 client.ts 既有 `post` 的实现**同款补一个**（这是 client.ts 的通用能力扩展，允许；不准绕开 client.ts 用裸 axios）。
- envelope 解析照 server.ts 现状（`ok()` 的 data 字段）。

## 2. 新增页面 `admin-web/src/views/server/CapabilitySettings.vue`

照 `ServerAddress.vue` 的骨架（PageHeader + LoadingBox + el-card）。内容三块：

**块1 · 全局模式**（el-radio-group，三个 el-radio-button）：

| 值 | 标签 | 副文案 |
|---|---|---|
| `hybrid` | 智能切换（推荐） | 优先本地引擎，失败自动用云端 |
| `local` | 纯本地 | 完全离线可用；本地引擎故障时报错 |
| `cloud` | 纯云端 | 与联网环境表现一致 |

- 默认选中 `GET` 返回的 `mode`；切换后**底部出现「保存」按钮**（不自动保存，防误触）；保存调 `setMode`，成功 ElMessage.success('已保存，立即生效')，失败走 BizError toast（client.ts 现有机制）。
- 保存中按钮 loading；防重复提交。

**块2 · 能力状态**（三行，能力名中文映射：tts=听写播报 / ocr=拍照批改 / asr=背诵判分）：

每行展示：
- 生效模式徽标（el-tag：local=info / hybrid=success / cloud=warning）；
- `local_ready` → 「本地引擎 ✅ {local_detail}」；否则「⚠️ 本地引擎未就绪：{local_detail}」；
- `locked=true` → 额外灰字「已被部署配置（.env）锁定，界面切换对该能力无效」。

**块3 · 说明文字**：一句「模式保存后立即生效，无需重启服务；正在进行的语音会话将在下一题应用新模式。」

## 4. 验收（无头浏览器冒烟，照 vue-admin-shell 的验收套路）

构建 + 起预览后用 Playwright/无头浏览器断言：
1. 菜单出现「AI 能力模式」项且可进入；
2. 三档 radio 渲染、默认选中与 GET 返回一致；

4. 三行能力状态渲染（local_ready 与后端实际一致：批次 B/C 未完成时 tts/ocr 的 local_detail 显示「模型未登记」也算正确渲染）；
