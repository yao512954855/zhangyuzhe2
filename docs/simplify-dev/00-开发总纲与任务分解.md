## 2. WBS 与并发批次

```
批次1  WP-F  大清理（串行，先行）           —— 删出干净地基
批次2  WP-A  后端数据层与接口（串行）       —— 新契约落地，B/C/D/E 的地基
批次3  WP-B ∥ WP-C ∥ WP-D（并行）
批次4  WP-E  错题本（串行，依赖 C/D 的页面）
批次5  WP-I  集成验收（独立 Agent，不采信各包自报）
```

依赖图：

```
F ──> A ──> B
        ├──> C ──┐
        └──> D ──┴──> E ──> I（集成验收）
```

- **为什么 F 最先**：F 删旧代码会触碰 B/C/D/E 周边文件，放最后必冲突（已裁决）。
- **为什么 A 串行**：001 契约（DDL/接口/枚举）要在代码里落地成真实可调的 API，
  B/C/D/E 才能用 Mock 之外的真实形状对齐。
- **为什么 E 不进批次3**：E 的「重做入口」要跳转 C/D 建的页面，页面不存在就没法接线。

## 7. 本机环境事实（写死，避免各包自查走偏）

- 端口：HTTP **8810**、UDP 发现 **9527**（全局互斥：任何真起 uvicorn 的测试不可并行）
- 后端 venv：`backend/.venv`；跑测试一律 `env -u PYTHONPATH .venv/Scripts/python.exe -m pytest`
- 全量 pytest 前必须**先停 dev 后端**（UDP 9527 撞车 → 假红）
- Flutter：用 `scripts/flutter.sh` 包一层跑（bash 直调 flutter 会崩）；
  gradle/pub 缓存已在脚本内指 D 盘热目录，**不得改**
- OCR：阿里云 RecognizeHandwriting，AK 在 `backend/.env`（OCR_ACCESS_KEY_ID/SECRET），
  端点 `ocr-api.cn-hangzhou.aliyuncs.com`；SDK 包名 `alibabacloud_ocr_api20210707`
  （清华镜像没有，走官方 PyPI）；**SDK 的 `Data` 字段是 JSON 字符串要二次 `json.loads`**
- 迁移：现有 `001_init.sql`、`002_wave2.sql`，新迁移必须是 **`003_simplify.sql`**
  （草案写 002 是笔误，已裁决改正）
