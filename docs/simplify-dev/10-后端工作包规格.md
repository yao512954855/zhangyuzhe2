## WP-F 大清理（批次1，串行）

**目标**：删掉简化版不需要的一切，让仓库成为干净地基。**只删不改**——
除下列「拆除性修改」外，不新增任何业务功能。

### F-1 删表

在 `003_simplify.sql` **之外**新建一次性清理迁移是禁止的——删表动作写进
`003_simplify.sql` 开头（`DROP TABLE IF EXISTS …`，含 §3.1 四张新表之外的
全部旧业务表）。即：**WP-F 只写 003 的「删旧」半段，WP-A 写「建新」半段**。
两半段文件独占：F 阶段文件里允许只有 DROP；A 阶段补全 CREATE。

### F-2 删后端模块

删除文件（连同对应测试）：
- `app/api/`：auth.py、appeals.py、classes.py、content_versions.py、gamify.py、
  hint.py、homework.py、live_board.py、me_learning.py、me_plans.py、
  me_profile.py、me_recitations.py、me_stats.py、recite.py、srs.py、stats.py、
  students.py、texts.py、units.py、words.py、imports.py、sessions.py
- `app/services/`：asr_log_service、asr_stats_service、class_service、
  content_service、gamify_service、homework_service、mastery_service、
  plan_service、recite/（整个语文背诵引擎目录）、srs_service、stats/、
  stats_service、user_service、version_service、session_service、judge_service*
- `app/schemas/`：auth.py、classes.py、content.py、imports.py、me_learning.py、
  recite.py、stats.py、student.py、session.py
- `app/core/`：audit.py（鉴权审计）
- 保留：api/{admin_static,asr_ws,discovery}.py、services/{asr/,discovery,
  settings_service,backup_service,import_service,judge,pinyin_service*}、
  core 其余全部

\* 两处保护性说明：
- `judge.py`（拼读判定）**保留**——WP-C 的 WS `letter` 消息靠它；其测试文件同步保留
- `pinyin_service` 与 `pypinyin` 依赖：语文删了它就没用。**保留文件但从
  requirements.txt 注释掉**，WP-C 集成时确认拼读判定不依赖它后再物理删除
  （写进跨包接力项；若判定依赖，恢复注释并报告）

### F-3 拆鉴权（拆除性修改）

- `main.py`：删 `_ensure_admin_account`、`hash_password` import、ADMIN 启动逻辑；
  health 不动
- `core/deps.py`：删登录态依赖函数；`core/security.py`：删（bcrypt 等）；
  `core/idempotency.py`、`core/rate_limit.py` 保留但去鉴权相关分支
- `admin-web/src/router/guard.ts` 删除、`api/client.ts` 去鉴权头与 401 跳转；
  `views/Login.vue` 删除
- `student-app`：删 `features/{auth,homework,srs,english,config,mine}`、
  对应路由注册、启动引导里的登录/注册流程（`features/bootstrap` 只保留
  连接与 UDP 发现部分）
- `requirements.txt`：删 `bcrypt`、`pypinyin`（先注释，见 F-2 说明）、
  `python-multipart` 保留（OCR 上传还要用）
- 数据库迁移执行后 `users` 表消失：`.env` 的 `ADMIN_INIT_*`、`JWT_*` 键删除

## WP-A 后端数据层与接口（批次2，串行）

**目标**：把 01-契约 §3/§4 完整落地。C/D/E/B 的地基，**实现必须与契约逐字一致**。

### 文件

- `app/migrations/003_simplify.sql`：补全 CREATE（F 已写 DROP 段）
- `app/api/{units,items,practice,wrongbook}.py`
- `app/api/dictation.py`：**本包只建文件与路由壳**（501 占位返回 `20005`），
  真实现归 WP-D（文件独占随之移交 D，见 00-总纲 §3 的批次说明）
- `app/services/{unit_service,item_service,practice_service,compare_service,
  wrongbook_service}.py`、`app/services/dictation_service.py`（壳，同上）
- `app/schemas/simplify.py`：全部请求/响应 Pydantic 模型
- 测试：`app/tests/test_s2_units.py`、`test_s2_items.py`、`test_s2_practice.py`、
  `test_s2_wrongbook.py`

### 要点

- 复用 `core/pagination.py`、`core/excel.py`（导入导出直接用它，模板文件放
  `backend/templates/items_template.xlsx` 由代码生成）
- `practice/start` 组卷：该 unit+type 全量条目按 sort 排序下发；`session_id`
  用现有 idempotency/会话基建或自增字典均可，**不落库**（服务内存即可，
  进程重启丢会话可接受，App 重新 start）
- `settle` 写 practice_logs；`wrongbook/auto-add` UPSERT 语义见契约 §3.4
- **OCR 壳的 501 占位**：让 D 在批次3 把实现填进同一文件（独占权移交在
  00-总纲写明，D 不得改壳里已有路由路径）

## WP-D 听链路（批次3，后端部分 + 学生端部分）

### D-1 后端（文件从 A 移交来的 dictation.py / dictation_service.py）

- 按契约 §6.3 实现 `grade_handwriting`：SDK 调用（二进制 body、
  `need_rotate=True`）、`Data` 字段二次 `json.loads`、块排序 (y 行带 60px, x)、
  与 words 比对（忽略大小写/空格/连字符）、置信度 <85 标 `uncertain`
- 超时 15s（`OCR_TIMEOUT_S`）；异常映射 `20005`/`20006`
- `requirements.txt` 加 `alibabacloud_ocr_api20210707`（官方 PyPI，清华镜像没有——
  在 requirements 顶部注释写明）
- 单测：**全部 Mock SDK**（契约 §10.8），覆盖：全对、错一词、认错但 uncertain、
  图片坏 20006、超时 20005

### D-2 学生端（`features/dictation/` 全新）

- 设置页：报中文/报英文（单选）+ 播报间隔（默认 10s，范围 5~30，步进 1s）
- 播报页：flutter_tts 逐题播报；进度 `n/总`；「重听」只重播当前题；
  「暂停/继续」；播完自动停（进入批改引导页）；
  **播报节奏与判分无关**（纸上写，无实时对错）
- 拍照页：`image_picker` 拍照（若 pubspec 已有相机依赖则复用现名）→ 预览 →
  上传 `POST /api/dictation/grade`（multipart `file` + `words` 逐个 form 字段）
- 结果页：对 X · 错 Y + 逐题对错清单（错题标 recognized 实际识别值）；
  uncertain 的标「拿不准」；错题逐个调 `/api/wrongbook/auto-add`；
  停 3 秒自动跳回单元列表（与背链路结算一致）
- TTS 语言：报英文 en-US、报中文 zh-CN（契约 §8）
