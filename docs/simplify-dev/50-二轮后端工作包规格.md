## BE-12 练习、错题本与设置

### 目标
practice/start 数组化组卷、answer 判对写 mastered_at、wrongbook 三类过滤+批量移出、settings 接口。

### Out of Scope
- 005 迁移本身（BE-11；本包测试若需新列，用契约签名 Mock 或依赖 BE-11 的迁移文件**只读引用**）
- WS（BE-13）
- App/管理端消费

### 独占文件
```
backend/app/api/practice.py
backend/app/api/wrongbook.py
backend/app/api/settings.py                  （新建；main.py 自动发现路由，勿改 main.py）
backend/app/services/practice_service.py
backend/app/services/wrongbook_service.py
backend/app/services/settings_service.py
backend/app/tests/test_practice_r2.py        （新建）
backend/app/tests/test_wrongbook_r2.py       （新建）
backend/app/tests/test_settings_r2.py        （新建）
```

### 功能点
- **F12-1 start 多选**：`unit_ids`/`types` 数组（单数保留兼容；两者都传以数组为准）；组卷顺序 = types 按 word→phrase→sentence 分组 → 组内按 单元顺序（请求中 unit_ids 顺序）→ sort → id；session 快照 unit_ids/types 供 settle 回退。
- **F12-2 answer 判对留痕**：`correct=true` 时服务端 UPSERT wrong_book 并写 `mastered_at`（幂等：已有 mastered_at 不覆盖）；**删除现有「判对 DELETE wrongbook」的调用链**（v1.1 #4 废除——注意检查 App 不受影响，此接口行为只增不减）。
- **F12-3 settle**：写 practice_logs（unit_ids/types JSON）；请求缺省时回退 start 快照。
- **F12-4 wrongbook 查询**：`mode` 过滤（三值）、`status=unmastered|mastered|all`（默认 unmastered）、响应含 `mastered_at`。
- **F12-5 batch-resolve**：`{entries:[{item_id,mode}]}` 逐条置 resolved_at，返回 `{resolved:n}`，不存在条目跳过。
- **F12-6 settings**：GET 全量 / PUT 局部更新；值域校验（倒计时 1~10、dictation_hint ∈ zh|en），非法值 `10001`；只允许改白名单键。

### 验收用例（节选）
- U12-1 start(unit_ids=[b,a], types=["phrase","word"]) → items 顺序：先全部 word（a 单元 sort 序 → b）再 phrase，组内 单元→sort→id
- U12-2 start 单数 unit_id/type 行为与一轮完全一致（回归）
- U12-3 answer(correct=true) → wrong_book 出现 mastered_at 非空、resolved_at 为空；重复判对不覆盖时间戳
- U12-4 answer(correct=false) → auto-add 语义不变（wrong_count+1）
- U12-5 wrongbook?mode=spell_zh2en&status=mastered → 只返回已掌握
- U12-6 batch-resolve 混合存在/不存在条目 → resolved=n 只计成功数
- U12-7 PUT settings spell_verdict_countdown_s=0 → 10001；=5 → GET 返回 5
- U12-8 PUT settings 未知键 → 10001，其余键不受影响
- U12-9 settle 传 unit_ids/types → 落库 JSON 与请求一致；不传 → 回退 start 快照

## BE-13 WS verdict 重构

### 目标
按契约 §5 v1.3 重构拼读 WS：letter 废除、verdict 登场（松开后整词判定）、utterance 降级为纯回显。

### Out of Scope
- App 端消费（APP-12）
- 判定算法变更（复用 `services/judge` 现有谐音映射，只换调用时机）
- en2zh / listen / recite 既有链路（零改动）
- 倒计时逻辑（App 本地定时器，服务端不管）

### 独占文件
```
backend/app/services/asr/session_manager.py
backend/app/services/asr/local_provider.py
backend/app/services/asr/mock_provider.py
backend/app/services/asr/base.py             （仅在需要时；改动最小化）
backend/app/api/asr_ws.py                    （仅在需要时）
backend/app/tests/test_s2_practice.py
backend/app/tests/test_local_asr.py
backend/app/tests/test_be06_ws.py            （只允许修「因 letter 删除而挂」的用例）
```

### 功能点
- **F13-1 letter 废除**：`_on_utterance` 不再调 `_spell_feed`，只透传 utterance 消息（v1.0.4 透传行为保留）；letter 相关代码路径删除（`_spell_feed`/`_spell_index` 等一并清理或标记私有待删——以「无死代码」为准）。
- **F13-2 verdict**：收到 `end`（松开）→ 取本轮完整转写 → 谐音映射还原字母序列 → 与 item.en 字母序列（去空格/连字符，忽略大小写）**完全一致 = 对** → 下发 `{type:"verdict", correct, text, session_id, item_id}`。
- **F13-3 判错抑制**：verdict(correct=false) 后，本轮后续音频帧丢弃（不再产生 partial/utterance/verdict），直到下一次 start。
- **F13-4 verdict 后 final 行为**：verdict 是本轮终态；紧随的 final 照常下发（兼容），但**不得**再触发任何判定（无重复上报）。close（未松开就断开）不产 verdict。
- **F13-5 mock 同步**：mock_provider 适配（verdict 测试可用 mock 全链路跑）。
- **F13-6 回归红线**：test_be06_ws / test_local_asr 全量绿；`CAP_ASR=cloud` 部署锁不破坏；**UDP 9527 全局互斥**（跑全量前停 dev 后端，#104 教训）。

### 验收用例（节选）
- U13-1 start → 推音频（mock 脚本 "see aye tee"）→ end → 恰好一条 verdict{correct:true,text:"cat"}，**无任何 letter**
- U13-2 转写错（"bee aye tee"）→ verdict{correct:false}；之后再推音频 → 无 partial/utterance/verdict（抑制生效）
- U13-3 按住中 utterance 照常透传（text 非空）但不产生 letter/verdict
- U13-4 不发 end 直接 close → 无 verdict
- U13-5 verdict 后紧跟的 final 不触发第二次判定/第二条 verdict
- U13-6 二次 start（下一题）→ 抑制解除，链路正常
- U13-7 全量 pytest 绿（停 dev 后端后跑）
