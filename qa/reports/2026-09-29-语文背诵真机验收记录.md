## 二、缺陷与修复

### #100 🔴 对齐窗口「起点越靠后越占便宜」→ 全文背完只点亮 13/50

**根因**（`backend/app/services/recite/aligner.py::summarize`）

`Alignment.distance` 把**片段尾部未被认领的 `missing`** 也算成了错误。
而 `best_alignment` 的片段是 `target[start : start + len(actual) + window]`，**会在 `target` 末尾截断**：

```
起点越靠后 → 片段越短 → 尾部待删的 missing 越少 → distance 越小
```

→ 各候选起点的 `distance` **根本不可比**，离末尾近的错误起点反而赢。

**实测**（真 provider + 真引擎，`backend/scripts/_cn_trace.py`）：

```
feed('的背影', pos=21)      # 学生接着说「的背影」
  候选起点 22（真起点）: distance=20  matched=[22,23]   claimed_end=24
  候选起点 34（末尾的「的」）: distance=15  matched=[34]  claimed_end=37   ← 15 < 20，被选中
→ pos 从 21 直接跳到 37，中间 13 个已经背对的字全丢
```

**修复**

`summarize()` 的 `distance` **只累计认领区间**（`index < claimed_end`），与 `claimed_end` 的语义统一 ——
未认领的尾部是「学生还没背到」，既不算漏字、也不算错误。
`extra`（学生多念的内容）仍全额计入：它落在 `actual` 侧，与起点无关。

**验证**

| 手段 | 结果 |
|---|---|
| 同一条真链路复跑（`_cn_trace.py`） | **50/50**，且**每帧 `pos == matched`**（不再跳字） |
| 修复前 | 27/50（真机 13/50 同因，只是 partial 边界不同） |
| 新增 `TestAlignerWindowBias` 4 条 | 全绿 |
| **反向验证**（临时回退修复） | **3 条转红**<br>（第 4 条「短增量不跳字」因该用例的增量里没有歧义起点而恒绿，属预期） |

新增用例：
- `test_short_delta_after_long_match_does_not_jump` —— 短增量不得把指针推到 13 个字之后
- `test_full_recitation_matches_every_char` —— 按 16 个**真实 partial** 逐帧喂，必须 50/50
- `test_alignment_distance_ignores_window_size` —— 窗口 20 → 40，`distance` 不得变化
- `test_alignment_prefers_the_true_start_over_a_later_one` —— 择优必须选中真起点

**同时纠正一条「把 bug 写成规矩」的旧用例**

`test_be05_align.py::test_distance_counts_full_fragment` 原断言 `distance == 2`，
理由写的是「**含尾部未认领，否则不同起点不可比**」—— **恰好写反**。
已改名 `test_distance_excludes_unclaimed_tail`（断言 `distance == 0`），另补 `test_distance_does_not_depend_on_window`。
（属 dev/02 §八 #84「断言腐化」同类：**断言写死了当时的既有事实**。）

### #101 🔴 背诵页每个汉字的下沿被裁掉约 40%

**现象**：真机截图可见「二」只剩一横、「已」只剩一个口 —— 每个字只剩上半截。

**根因**（`student-app/lib/features/recite/widgets/char_grid.dart`）

「已背出」的格子是 `SizedBox(width/height = reciteBig * 1.12)`，里面 `Center` 一个 `Text`，
文字样式借用了**课文用**的 `reciteStyle`（`height: 2.0`，行盒 = 2.0em）：

```
SizedBox 给的是紧约束 → Center 只把约束放松到 maxHeight = 1.12em
→ RenderParagraph.size 被 constrain 到 1.12em → didOverflowHeight 成立
→ 它自己 clipRect 到被压矮的尺寸 → 汉字下沿被裁
```

⚠️ `AgeProfile.reciteLineHeight = 2.0` 是 **UI 规范 §3.3 给多行课文**的行间距，
对「一个字一个格子」没有意义、只有副作用。

**修复**：新增 `_cellLineHeight = 1.15`（单格行盒）与 `_cellSizeFactor = 1.25`（单元边长），
格内 `Text` 用 `height: _cellLineHeight`、不再借用课文行高；不变量「单元高必须 > 行盒」写进注释。

**验证**：新增 widget 用例「回归：汉字不得被裁掉下沿（行盒必须装得进单元格）」——
用与组件**同一份 style** 跑 `TextPainter` 量出行盒，断言「行盒 ≤ 渲染盒」+「行盒 ≤ 单元格高」
（纯渲染层，`find` / 尺寸 / `analyze` **全都看不出来**，这是唯一可自动化的口径）；
**反向验证**：把行高/单元恢复旧值 → 该用例**立刻转红**；`test_app04_recite_test.dart` **28 passed**。

### #102 🟡 「首次发声延迟」显示 66:27（真身 3.99 秒）

**根因**（`student-app/lib/features/recite/recite_page.dart`）：

### #103 🟡 结算之后再进背诵 → 「背诵已过期」（**待裁，本次未改代码**）

**证据链**

1. `recitations.id=7` 已结算（`finish_reason='manual'`）→ `ReciteService.settle()` 调 `_drop_engine()` **销毁内存引擎**。
2. 之后 App 又开一路 WS 并以**同一个 `recitation_id=7`** 发 `start` → `feed` 时 `_peek_engine()` 返回 `None`
   → 抛「背诵已过期，请重新开始」（`asr/session_manager.py:754`）。日志：`06:03:41 背诵 feed 失败：背诵已过期`。
3. 同一时段另有两条 `ASR end 在 start 之前到达 user=2`（在**没有 `start`** 的会话上发 `end`）。
4. `recitation_events` seq `67~69` 是**客户端补报**的 `restart`（`report_events` 接在服务端事件之后）
   → App 侧记了 **3 次**「重新开始本段」，而对应 HTTP 调用**全部失败**。

**两层隐患**

| 层 | 问题 |
|---|---|
| 服务端 | `_resolve_recitation()` 的**显式 `recitation_id` 分支没有 `finished_at IS NULL` 过滤**（只有「按 `text_id` 找最新未结算」的兜底分支有）→ 会把**已结算**的背诵解析出来交给 WS |
| App | `_startRecording()` 只看 `state.create != null`，**不区分是否已结算** → 复用同一个 `recitationId` |

**待裁**：
- **A** App 侧结算后一律**新建背诵**（`ReciteController` 加 `settled` 标记，进页时强制重建）——推荐，最贴合「再背一次」的语义
- **B** 服务端回一个**可区分**的错误（「本段已结算，请重新开始」+ 专用 code），App 收到即自动新建
- **C** 两者都做

> 要动 App 状态机且需真机复验，**本次未擅自改动**。

### 5.3 🔴 新发现 #105（待裁 · **严重**）语文流式背诵必撞写接口限流

真机中途弹出 `操作太频繁了，请稍后再试（编号 80bbd57004ba）`。

- 数日志：**`07:05` 这一分钟 WS 出帧 `type=partial` 共 71 个**。
- `recite_page.dart::_onWsMessage()` 对**每个** partial 都 `POST /api/recitations/{id}/feed`
  → 71 次写请求 > `rate_limit.WRITE_LIMIT = 60`（契约 §5.4 单账号写接口 60 次/分钟）→ 中间件回 `10005`。
- ⚠️ **流式 ASR 正常语速就是 40~70 partial/分钟 → 每场语文背诵都会撞**。
- 更关键：**服务端早已把进度塞进 WS 帧**（`session_manager._on_partial()` → 同帧的 `"recite"` 字段），
  App 只读 `msg['text']` 丢弃 `msg['recite']` 再走 HTTP → **重复喂 + 白烧配额**。
- 副作用：`feed` 失败按设计不阻断录音 → 学生继续念、**网格不再点亮**（观感「背了不亮」）。
- 方案见 `dev/02 §八 #105`（A 推荐 / B 保守 / C 须裁）。
